## 🎯 What Worked Well

### 1. **Extract the logic to a pure, node-tested module first (alpha A)**
- Pulled the wizard's organize logic into `organizeEngine.js` — no React, no globals, `require()`-able — with 8 node tests encoding the rules (series threshold, flat vs nested, merge/dedup, purity).
- The wizard and the new right-click share ONE engine (`computeOrganizePlan`/`groupBooksBySeries`); the right-click inherited correct behavior for free.
- **Lesson**: For a feature that reuses existing logic, extract that logic to a pure module *before* adding the new UI. It doubles as regression protection for the old path and a spec for the new one.

### 2. **Pre-planned the extractability fallback and honored it**
- The design doc said "reuse the explorer cover *if it extracts cleanly; otherwise purpose-built.*" On inspection the explorer's grid cover was ~150 lines fused to drag-reorder, virtualization, and the All-Books tooltip — not cleanly extractable.
- Fell back to a small purpose-built preview cover instead of forcing a risky refactor, while still reusing the *data* accessors (`getFoldersContainingBook`, `getBookListsContainingBook`, `addBooksToBookList`).
- **Lesson**: Decide the fallback before you look. It turns "reuse vs rebuild" from a sunk-cost trap into a quick call.

### 3. **Incremental alphas, each committed before a local browser test**
- 10 small iterations, each user-tested locally. This caught the semantics mismatches and the undo regression within an alpha or two rather than at release.

### 4. **A bug report became a systemic decision**
- "No toast when I delete a folder" investigation surfaced **three drifted folder-delete handlers** (different confirm text, one missing the toast, two divergent DELETE_FOLDERS undo payloads). Rather than patch the one path, we agreed on an operations single-source-of-truth refactor.
- **Lesson**: When a bug is an *instance* of duplication, name the class and fix it there.

### 5. **Genuine UX partnership**
- The ellipsis on "By Author…/By Series…" (signals "opens a dialog" — reassures the click), the numeric stepper over a checkbox for the series threshold, and the honest difficulty/risk call on double-click + stale-refresh — all landed as real design reasoning, including changing my own initial position.

## ❌ Mistakes Made

### 1. **Mis-modeled the operation semantics — twice**
- First built **By Author** as the full Author/Series hierarchy; Ron's model is **flat** (all books under the author, no subfolders). Then built **By Series** as *series-scoped* (only the one series' books); his model is **author-scoped with series subfolders** (so the standalone gets filed too, not left behind). Cost two rework alphas (alpha.5, alpha.6).
- **What should have happened**: state the structural model back with a concrete example ("By Author on Mick Herron → both books flat under 'Mick Herron', no Slow Horses folder — yes?") *before* coding.
- **Fix**: new feedback memory — confirm user-facing operation semantics with an example before building.

### 2. **Undo regression from my own refactor (alpha.1 → alpha.2)**
- The alpha.1 refactor computed `plan` *inside* the `setFolders(updater)` callback, which React runs deferred — so the very next line's `recordAction` saw a null plan and undo was silently dropped.
- **Fix (alpha.3)**: compute the plan synchronously up front, then `setFolders(plan.newFolders)` and `recordAction`. The shared `applyOrganizePlan` now enforces this order for both wizard and right-click.

## 📚 Lessons Learned

### 1. **Pure-module tests validate LOGIC, not INTEGRATION**
- All 8 engine tests passed the entire time undo was broken — because the bug lived in React wiring, not the engine. Unit tests for the pure core are necessary but not sufficient; the stateful wiring still needs a manual/integration pass.

### 2. **The React deferred-updater trap**
```js
// WRONG: plan is assigned in a deferred updater; the next line sees null
setFolders(prev => { const plan = compute(prev); return plan.newFolders; });
recordAction({ subActions: plan.subActions }); // plan is undefined here

// RIGHT: compute synchronously, then apply
const plan = compute(folders);
setFolders(plan.newFolders);
recordAction({ subActions: plan.subActions });
```
Never read a value assigned inside a state updater on the next synchronous line.

### 3. **The "survives Cancel" test for undo granularity**
- Ron half-expected the in-preview "add to Book List" + "Organize" to be one undo. They stay two, and the deciding principle is: **an action that commits immediately and survives Cancel is not part of the confirm transaction** — it deserves its own undo. Bundling would also forbid a legitimate want (undo the filing, keep the queue). Good reusable rule for future compound-vs-separate undo calls.

## 🤖 AI Collaboration Insights

### Practices That Required User Prompting
- Ron had to ask for the **pure** UX opinion (threshold control): my first lean (checkbox) had smuggled in implementation/simplicity bias; asked to strip that, I flipped to the numeric stepper. Reminder to separate "what's easy to build" from "what's best for the user" when asked for a UX verdict.
- The operation-semantics confirmation (above) was surfaced by his correction, not by me asking up front.

### What Ground Rules Helped
- **Alpha-commit-before-test** kept every iteration recoverable and bisectable.
- **STOP-and-ask on discussion/UX questions** — the ellipsis and undo-granularity turns were discussion-first, code-later.
- **Divergence pre-flight** (from the 6.12.0 lesson) paid off: this time prod/main hadn't moved, so a clean fast-forward — verified rather than assumed.

## 🔄 Rule Updates Made/Proposed

### Proposed feedback memory: confirm operation semantics before building
- For a user-facing action whose *structure* matters (what folders/nesting it produces), restate the model with a concrete example and get a yes before coding. Motivated by the two By Author/By Series rework alphas.

Otherwise: existing rules were sufficient when followed.

## Final Thoughts

A clean, well-sequenced feature: a pure engine underneath, an incremental UI on top, and a real UX conversation throughout. The two stumbles — mis-modeling By Author/By Series, and breaking undo with a deferred-updater refactor — were both caught fast by the alpha-test loop, and both point at the same discipline: pin down *exactly* what the user means and *exactly* when React runs your code, before you build on either.

**Key Takeaway**: Extracting the logic to a pure, tested module was the win; the reminder is that pure tests don't cover React wiring — confirm the semantics and re-test the stateful paths (undo!) by hand.
