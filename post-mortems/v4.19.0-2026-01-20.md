# Post-Mortem: v4.19.0 - Wishlist Persistence & Data Model Cleanup

**Release Date:** 2026-01-20
**Version:** 4.19.0

## Summary

This release completes the wishlist persistence feature, ensuring wishlist books survive library re-imports and receive full enrichment during Phase 2 gap-fill operations.

## What Was Built

### Phase 1: Fix Import to Preserve Wishlist
- Modified `loadLibrary()` in readerwrangler.js to preserve existing wishlist items when importing new library data
- Import now merges rather than replaces, preventing loss of manually-added wishlist books

### Phase 2: Data Model Cleanup
- Introduced `onWishlist` boolean and `ownershipType` enum ('owned' | 'sample' | 'ku' | 'wishlist')
- Legacy fields (`isOwned`, `isWishlist`) converted via `normalizeBook()` with 6-month deprecation window (until 2026-07-20)
- Organizer UI updated to use new data model

### Phase 3: Dynamic Enrichment for All Books
- Verified gap-fill enrichment includes wishlist items (filters by `!b.description`, not ownership)
- Moved `booksWithoutDescriptionsDetails` from JSON output to console-only logging
- Removed obsolete `booksWithoutDescriptions` tracking from readerwrangler.js metadata

### Phase 4: Export Includes All User Metadata
- Added missing fields to `exportLibrary()`: `targetPrice`, `currentPrice`, `listPrice`, `priceAsOf`, `genres`, `genresAsOf`
- Confirmed wishlist books export correctly in both legacy and new formats

## Issues Encountered

### 1. ORGANIZER_VERSION Increment Error
**What happened:** When releasing, I incorrectly changed ORGANIZER_VERSION from 4.18.0.d to 4.19.0 instead of simply dropping the letter suffix to 4.18.0.

**Root cause:** Confused APP_VERSION (incremented at release time) with ORGANIZER_VERSION (incremented during development, letter suffix dropped at release).

**Resolution:** User caught the error. Fixed by setting ORGANIZER_VERSION to 4.18.0.

**Lesson:** APP_VERSION and ORGANIZER_VERSION are independent:
- ORGANIZER_VERSION: file build version, increments during development (a→b→c), drop letter at release
- APP_VERSION: release version for the whole app, incremented only at release time

### 2. Missing v4.18.0 Tag
**What happened:** Discovered commit `db55bdd` had set APP_VERSION to 4.18.0 but was never tagged in git.

**Root cause:** Previous release process skipped tagging step.

**Resolution:** Created tag v4.18.0 pointing to the existing commit `db55bdd`, added CHANGELOG entry retroactively.

**Lesson:** Always verify tag creation after release. Consider adding a checklist item to verify tags exist.

## Lessons Learned

1. **Read the rules carefully** - The release rules clearly state "drop the letter suffix" not "increment the version again"
2. **Version management requires attention** - Two different version numbers (APP vs file) serve different purposes
3. **Git history is the source of truth** - When confused about releases, investigate git history rather than guessing
4. **Retroactive tagging works** - Can tag historical commits when releases were missed
