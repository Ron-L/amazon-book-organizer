## 🎯 What Worked Well

### 1. **One-question analysis before acting**
- "Does 'Load from credentials file' already accept full backups?" — one read of the handler confirmed yes (`data.relay.channelId + passphrase` extracted from any JSON). That single check unlocked the decision to remove the Backup button and rename the label with confidence.
- **Lesson**: Read the existing behavior before proposing a change. One targeted grep often answers the key question.

### 2. **Callout box > footnote**
- Original demo copy was two plain centered paragraphs — easy to overlook. User flagged it. Replacing with an amber callout box (left accent, rounded corners, light yellow bg) made it a visible element, not a footnote.
- **Lesson**: For new-user onboarding copy on a landing page, plain text paragraphs compete poorly with everything else. A styled callout box is the minimum viable visibility treatment.

### 3. **Relative URL for `download` attribute**
- Initial implementation used the full raw GitHub URL. The `download` attribute is silently ignored for cross-origin URLs by browsers — which means the link opens the raw JSON instead of triggering a save dialog.
- User tested on local server first (worked), then identified the question about GitHub Pages behavior, which confirmed relative URL was correct.
- **Lesson**: `<a download>` only fires for same-origin URLs. For assets served from the same domain, always use a relative URL.

### 4. **`.gitignore` exception syntax**
- `*-library.json` was catching `readerwrangler-demo-library.json`. Fixed with a `!readerwrangler-demo-library.json` negation line immediately after the wildcard.
- **Lesson**: When a file matches a `.gitignore` wildcard pattern but should be tracked, add a `!filename` exception directly below the wildcard — proximity makes the intent clear.

## ❌ Mistakes Made

### 1. **Used full raw GitHub URL for `download` link**
- Set `href="https://raw.githubusercontent.com/..."` — cross-origin, so `download` attribute was silently ignored. Required a second alpha.
- **What should have been done**: Know that `download` only works same-origin. Use relative URL when the file is served from the same domain.

### 2. **Demo copy as plain paragraphs**
- Initial implementation was two `<p>` tags with `text-align: center` — visually indistinguishable from surrounding body text. User had to point out it would be overlooked.
- **What should have been done**: New-user onboarding callouts on landing pages need visual treatment from the start. Propose the callout box before coding, not after user feedback.

## 📚 Lessons Learned

### 1. **`download` attribute and cross-origin**
The HTML `download` attribute is silently ignored for cross-origin URLs (security restriction). It only triggers a save dialog for same-origin resources. Use relative URLs for downloadable assets served from the same domain.

### 2. **Landing page onboarding copy needs visual treatment**
Plain paragraphs are invisible on a content-rich landing page. Any new-user callout — especially one introducing a key feature — needs a styled container: background color, border, rounded corners. An amber left-accent callout reads as "tip" without alarming the user.

### 3. **Validate saved state after load with a loading-gated useEffect**
For state restored from localStorage that may reference deleted entities (folder IDs, etc.), add a `useEffect` gated on `syncStatus !== 'loading'` that validates the saved value against current data. If invalid, reset to a safe default. This pattern cleanly handles stale references without complicating the save/restore logic.

### 4. **Check what existing handlers already accept before adding a new one**
Before adding a new file handler or export format, read the existing one first. The "Load from credentials file" handler already accepted full organizational backups (`data.relay` key present in any backup). No new handler needed — just remove the redundant export and update the label.

## 💡 Recommendations for Future

### 1. **Test downloadable links cross-origin before committing**
Any `<a download>` link pointing outside the current origin won't work. Always use a relative URL for same-domain assets.

### 2. **New-user onboarding: styled callout from the start**
When writing copy that targets first-time users on a marketing page, start with a callout box. The cost of adding styling after feedback is low, but it's avoidable with a single upfront decision.
