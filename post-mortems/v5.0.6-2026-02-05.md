## What Happened

### The Problem

Hidden books had no visual feedback in v5.0.0+ Book Explorer:
- Hide/Unhide context menu worked correctly
- `hiddenInstances` state tracked correctly
- But books looked identical to non-hidden books
- No opacity change, no overlay icon

User expectation from v4: "Hidden books display with 40% opacity + large 🚫 overlay"

### Root Cause

**v5.0.0 Book Explorer refactoring never migrated visual styling from v4.**

The migration path:
1. **v4 Column App** had hidden book visual styling (opacity + overlay)
2. **v5.0.0** rewrote UI as Book Explorer with new List/Cover views
3. **v5.0.2** deleted v4 Column App code (~470 lines, including visual styling)
4. **Context menu functionality** was preserved in new code (lines 11600, 13734)
5. **Visual styling** was never added to new rendering code

**Why was it missed?**
- Focus during v5.0.0 development was on new Explorer features (folders, drag-drop)
- No explicit feature parity checklist between v4 and v5
- Developer may not have had hidden books in test library
- Visual feedback is easy to overlook if feature still "works" functionally

### The Fix

**Added visual styling to both List and Cover views:**

1. **List View - Row Opacity** (line 10440-10454):
   - Check if `hiddenInstances.has(book._instanceId) || book.isHidden`
   - Set `styles.opacity = 0.4` for hidden books
   - Cut opacity (0.5) takes precedence if book is both cut and hidden

2. **List View - Thumbnail Overlay** (line 10578-10585):
   - Wrap `<img>` in relative positioned div
   - Add centered 🚫 emoji (text-2xl) for hidden books

3. **Cover View - Card Opacity** (line 10897-10912):
   - Same opacity check pattern as list view
   - Set `styles.opacity = 0.4` for hidden books

4. **Cover View - Cover Overlay** (line 11009-11016):
   - Wrap cover image in relative positioned div
   - Add centered 🚫 emoji (text-8xl, larger for visibility) for hidden books

**Dual-format compatibility:**
- Check both `hiddenInstances.has(book._instanceId)` (current, v4.16.0+)
- AND `book.isHidden` (legacy, pre-v4.16.0)
- Ensures old data formats still work

## Lessons Learned

### 1. **Feature Parity Checklist for Major Refactorings**

This is now the **third v4 feature** lost in v5.0.0 transition:
- v5.0.2: viewMode (orphaned code)
- v5.0.4: Wishlist filter (missing from UI)
- v5.0.6: Hidden book styling (visual feedback)

**Pattern:** Functional logic preserved, UI/visual elements lost.

When doing major UI rewrites, create explicit checklist:

**Functional Features:**
- [ ] List all v4 user actions (right-click menus, buttons, shortcuts)
- [ ] Map each action to v5 implementation
- [ ] Test each action works identically

**Visual Features:**
- [ ] List all v4 visual feedback (colors, opacity, icons, overlays)
- [ ] Map each visual cue to v5 rendering
- [ ] Test each visual cue appears correctly

**Example for v5.0.0:**
```
Hidden Books Feature:
  Functional: ✅ Hide/Unhide context menu works
  Functional: ✅ hiddenInstances state tracked
  Functional: ✅ Show Hidden checkbox works
  Visual: ❌ Opacity styling (MISSING)
  Visual: ❌ 🚫 overlay (MISSING)
```

### 2. **Test Library Should Include Edge Cases**

Developer test library should always include:
- Hidden books (various states)
- Wishlist books (owned + wishlist)
- Books with missing data (no cover, no description)
- Books in folders (various depths)
- Books with tags, ratings, notes
- Very long titles, series names

Don't just test with "clean" sample data.

### 3. **Visual Feedback is Critical UX**

Context menu works ≠ feature works.

Users need visual confirmation that:
- Their action had an effect (book was hidden)
- The state persists (book stays hidden after page refresh)
- They can distinguish hidden books from visible books

Missing visual feedback = feature appears broken.

### 4. **Dual-Format Data Compatibility**

When data models evolve (`book.isHidden` → `hiddenInstances`), always check BOTH formats in UI code:

```javascript
// Good: Checks both current and legacy formats
if (hiddenInstances.has(book._instanceId) || book.isHidden) {
    styles.opacity = 0.4;
}
```

This prevents breaking old backups or partial migrations.

### 5. **Post-Mortems Reveal Patterns**

All three missing v4 features share the same root cause: **no systematic feature migration audit**.

After this release, should do a comprehensive v4→v5 feature audit to catch any remaining gaps.

## Technical Details

**Hidden State Evolution:**
```javascript
// Pre-v4.16.0: Boolean flag on book object
book.isHidden = true;

// v4.16.0+: Set of instance IDs for per-instance hiding
const [hiddenInstances, setHiddenInstances] = useState(new Set());
hiddenInstances.has(book._instanceId); // Check if hidden
```

**Visual Styling Implementation:**

**List View Row Opacity:**
```javascript
// Line 10440-10454
style={(() => {
    const styles = {};
    // Hidden book visual feedback (check both formats)
    if (hiddenInstances.has(book._instanceId) || book.isHidden) {
        styles.opacity = 0.4;
    }
    // Cut takes precedence
    if (clipboard?.type === 'cut' && clipboard?.bookIds?.includes(book.id)) {
        styles.opacity = 0.5;
    }
    return styles;
})()}
```

**List View Thumbnail Overlay:**
```javascript
// Line 10578-10585
<div className="relative" style={{ minWidth: '32px', maxWidth: '48px' }}>
    <img src={book.coverUrl} alt="" className={`h-12 object-contain rounded ${book.onWishlist ? 'opacity-40' : ''}`} />
    {/* Hidden book overlay */}
    {(hiddenInstances.has(book._instanceId) || book.isHidden) && (
        <div className="absolute inset-0 flex items-center justify-center text-2xl pointer-events-none">🚫</div>
    )}
</div>
```

**Cover View Overlay:**
```javascript
// Line 11009-11016
<div className="relative">
    <img src={book.coverUrl} alt={book.title} className={`w-full h-auto rounded shadow ${book.onWishlist ? 'opacity-40' : ''}`} />
    {/* Hidden book overlay */}
    {(hiddenInstances.has(book._instanceId) || book.isHidden) && (
        <div className="absolute inset-0 flex items-center justify-center text-8xl pointer-events-none">🚫</div>
    )}
</div>
```

**Emoji Size Reasoning:**
- List view: text-2xl (24px) - thumbnail is small (48px max-width)
- Cover view: text-8xl (96px) - cover is large (variable width, ~150-200px typical)
- User feedback: "at least 3X in size" for cover view
- Progression: text-4xl (36px) → text-8xl (96px) in alpha.2

**Why Separate Divs?**
- Need `position: relative` on wrapper for `absolute` positioning of overlay
- Can't apply both to same element due to CSS stacking context
- `pointer-events-none` ensures overlay doesn't block clicks

**Opacity Precedence:**
Hidden (0.4) applied first, then Cut (0.5) overwrites if both true.
- Hidden only: 0.4 opacity ✅
- Cut only: 0.5 opacity ✅
- Both: 0.5 opacity (cut wins) ✅

This makes sense because cut is a temporary action (clipboard), hidden is permanent state.
