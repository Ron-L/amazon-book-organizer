# Post-Mortem: v4.20.1

**Date:** 2026-01-22
**Release Type:** Bug Fix

## Summary

Fixed navigator bookmarklet creating duplicate stacked modals when clicked rapidly on slow machines.

## What Changed

### Bug Fixes
1. **Duplicate modal prevention** - Added dialog ID check at script start to prevent creating multiple modals
   - File version: bookmarklet-nav-hub.js v1.2.3
   - If modal already exists in DOM, script returns early (does nothing)

## Root Cause Analysis

The navigator bookmarklet IIFE created a new dialog element on every invocation without checking if one already existed. On slow machines, users would click the bookmarklet multiple times before the modal appeared, resulting in stacked dialogs.

## Discovery

Identified during TODO review as a known issue affecting users with slower computers.

## Fix Implementation

Simple 3-line fix:
1. Define a constant dialog ID: `'readerwrangler-nav-dialog'`
2. Check `document.getElementById(DIALOG_ID)` at script start
3. If exists, log message and return early
4. Assign the ID to the dialog element when creating it

## Design Discussion

Initial proposal included "bring to front" logic (increasing z-index), but analysis showed this was unnecessary:
- Each browser tab has its own DOM - no cross-tab concerns
- To click the bookmarklet again, user must have browser toolbar visible
- If toolbar is visible, modal at z-index 10000 is already visible
- Simply preventing duplicate creation is sufficient

## Testing Performed

1. Local testing with rapid bookmarklet clicks
2. Verified only one modal appears regardless of click frequency
3. Verified console shows "Navigator dialog already open" on duplicate attempts

## Lessons Learned

1. **DOM elements should have IDs** - Makes duplicate detection trivial
2. **Question initial assumptions** - "Bring to front" logic wasn't actually needed once the problem was analyzed properly
