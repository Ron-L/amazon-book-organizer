## 🎯 What Worked Well

### 1. **Iterative visual refinement with screenshots**
- User provided screenshots at each alpha, enabling rapid targeted fixes: transparent border fighting the stripe, missing colors, icon size, banner clarity.
- **Lesson**: For UI work, screenshot-driven iteration is fast and precise. Each round of feedback collapsed multiple ambiguities at once.

### 2. **UX expert framing**
- Asking "put on your UX expert hat" repeatedly produced good design outcomes: the 'none' sentinel for accordion toggle, all steps starting collapsed, removing the GIF placeholder, the pulsing tower icon instead of a checkmark.
- **Lesson**: Framing questions as UX expert evaluations (not just implementation questions) leads to better design before code is written.

### 3. **Wrapper div approach for the left accent stripe**
- The first two attempts (borderLeft on button, then on body div) both failed visually — transparent border on closed sections diluted the contrast of the open one. The wrapper div approach (borderLeft: 'none' on closed, colored on open) fixed it cleanly.
- **Lesson**: When a visual property on sibling elements competes, put it on a shared parent wrapper instead. No "transparent placeholder" borders.

### 4. **Sentinel value for accordion state**
- `null` = "modal just opened, auto-open default" vs. `'none'` = "user explicitly closed" solved the toggle problem cleanly without a useEffect or complex logic.
- **Lesson**: A sentinel string value is often cleaner than a boolean for distinguishing "not set yet" from "explicitly cleared."

## ❌ Mistakes Made

### 1. **Four attempts to get the left stripe working**
- Tried: (1) borderLeft on button with transparent fallback, (2) borderLeft on body div, (3) 60px test to confirm. Each had a different root cause. Should have recognized the "transparent border creates implicit spacing on all elements" problem earlier.
- **What should have been done**: Think through all elements that receive the border property (including closed ones) before choosing the approach.

### 2. **Missed CSS variable fallbacks for test status colors**
- Used `var(--text-success, #16a34a)` and `var(--text-danger, #dc2626)` — the variables weren't defined in this app's theme, and the fallback didn't render. Required a second pass to use direct hex colors.
- **What should have been done**: Prefer direct hex for one-off UI colors; only use CSS variables for colors that are part of the design system and confirmed defined.

### 3. **`activeSection` auto-open fought user intent**
- `const activeSection = relaySetupSection || (hasCreds ? 'bookmarklet' : 'credentials')` meant closing a section (setting to null) immediately reopened it. Took several rounds of user feedback to diagnose.
- **What should have been done**: When designing accordion state, explicitly decide upfront whether "null" means "auto-open default" or "everything closed." They can't mean both.

### 4. **relayTestStatus not reset on all close paths**
- Added reset only to the Done/Close button footer. Missed X button (line 7855), backdrop click (line 7851), and ESC key (line 4755). User confirmed it persisted across opens.
- **What should have been done**: When adding state reset to a close action, grep for ALL close paths in the same modal before committing.

### 5. **Show All row condition too broad**
- `{hasActiveFilters && (` showed the row whenever any filter was active, even when all folders still matched. The spec was clear: show only when filters are *hiding* folders.
- **What should have been done**: Re-read the spec condition precisely before implementing. "Filter active" ≠ "filter hiding something."

## 📚 Lessons Learned

### 1. **"Transparent border" creates implicit spacing on siblings**
When you use `borderLeft: 'Xpx solid transparent'` on closed accordion items to reserve space, you're allocating X pixels of gutter on EVERY item — open and closed. This reduces the visual contrast of the colored border on the open item. Use `borderLeft: 'none'` (or a wrapper div with conditional borderLeft) instead.

### 2. **Accordion state needs an explicit sentinel for "user closed"**
Three-state model: `null` = initial/auto, `'none'` = explicitly closed, `'id'` = explicit open. Without the sentinel, any "close" action (setting to null) triggers the auto-open fallback.

### 3. **Grep for all close paths when adding state cleanup**
Any state that should reset on modal close needs to be reset in ALL paths: footer button, X button, backdrop click, ESC key handler. Scan for all `setModalOpen(false)` occurrences in the file before marking done.

### 4. **CSS variables for one-off UI colors**
Use direct hex for custom status colors (`#16a34a`, `#dc2626`). Only use CSS variables for colors defined in the shared design system. Undefined variables with fallbacks work but are fragile and harder to debug.

### 5. **Condition precision: "filter active" ≠ "filter hiding something"**
For filter indicator rows, always compute the actual affected count and gate visibility on `affectedCount > 0`, not on `filterActive`. The IIFE pattern used in the row is the right structure — move the null guard to the top of the IIFE.

## 🔄 Rule Updates Made/Proposed

### New patterns to remember
- **Accordion sentinel**: use `'none'` for "user explicitly closed", `null` for "uninitialized/auto-open". Never conflate.
- **Modal state reset**: grep for all close paths before marking state cleanup done.
- **Wrapper div for visual stripe**: conditional border on a wrapper div; never transparent-border on siblings.
- **Condition precision**: filter indicator rows check `affectedCount > 0`, not just `filterActive`.

## 💡 Recommendations for Future

### 1. **Modal state checklist**
When adding any state that belongs to a modal, create a mental checklist: (a) what initializes it, (b) what resets it, (c) are ALL close paths covered? This prevented the relayTestStatus bug but only after it was reported.

### 2. **UI-heavy features: design before code**
The Relay Setup redesign took 12 alphas partly because visual design decisions were made incrementally. A rough sketch or written spec of the final design (stripe on wrapper, all closed by default, tower icon on right) before alpha.1 would have collapsed this to 3-4 alphas.

## Final Thoughts

A feature-rich release that took longer than expected due to accumulated UI iteration. The Relay Setup redesign alone went through 9+ alphas — mostly on visual details (stripe visibility, badge design, accordion state) rather than functional bugs. The pulsing tower icon and the clean accordion with 18px left stripe are the visual highlights. The bookmarklet `s.onerror` closes a long-standing silent failure gap.

**Key Takeaway**: For UI-heavy work, invest more time in the design spec before alpha.1. Screenshot-driven iteration is effective but expensive — each round takes a full cycle. A written agreement on the final design state reduces the rounds needed.
