# v4.24.1 Post-Mortem - Library Fetcher Save Gesture Fix

**Release Date:** 2026-01-24
**Duration:** ~20 minutes (diagnosis + fix + release)

## What Was Fixed

### User Gesture Requirement for File Save
- `createWritable()` on FileSystemFileHandle requires an active user gesture
- Original gesture from file picker expires during long fetch operations (45+ seconds)
- If user navigates away during fetch, gesture definitely expires
- Error: `SecurityError: User activation is required to request permissions`

## Root Cause

The `amazon-library-fetcher.js` had inconsistent handling between two save paths:

1. **Full fetch (no existing file)**: Already showed "Save Library File" button to provide fresh gesture before `showSaveFilePicker()` - **worked correctly**

2. **Re-run (existing file handle)**: Directly called `fileHandle.createWritable()` without fresh gesture - **broken**

The `amazon-collections-fetcher.js` already had the correct pattern for both cases.

## Technical Implementation

### Fix Applied (lines 2182-2205)
- Added `showSaveButton()` call before `createWritable()` in fileHandle branch
- Added try/catch for save errors
- Added cancel handling
- Matches pattern from collections-fetcher

### Code Change
```javascript
// Before (broken):
if (fileHandle) {
    const writable = await fileHandle.createWritable(); // No gesture!
    ...
}

// After (fixed):
if (fileHandle) {
    const userChoice = await progressUI.showSaveButton(finalBooks.length);
    if (userChoice === 'cancel') { return; }
    try {
        const writable = await fileHandle.createWritable(); // Fresh gesture!
        ...
    } catch (e) { ... }
}
```

## Lessons Learned

1. **File System Access API quirks** - User gestures expire; long operations need fresh gestures
2. **Consistency matters** - When fixing an issue in one fetcher, check all fetchers for same issue
3. **UX consideration** - Users will navigate away during long operations; design for this
