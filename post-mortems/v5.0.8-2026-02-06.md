## What Happened

### The Problems

**Issue 1: Misleading error messages (P0-T1 from TODO)**
- Book reorder messages said "Cannot reorder in All Books" but didn't explain WHY
- Folder reorder messages said "Switch to Manual Order" (generic, unclear)
- Both messages lacked context about what the user should do instead

**Issue 2: UX catch-22 in My Library (discovered during work)**
- User tried to reorder folders in My Library
- Got message: "Change sort to Manual Order to reorder folders"
- But Manual Order switching was disabled/grayed out (couldn't click ✕ button)
- Tooltip said: "My Library is a read-only view - no manual ordering"
- This contradicted intentional design: folders CAN be reordered in My Library

**Issue 3: Reset App error (discovered during testing)**
- Reset App function called `setViewMode('columns')` at line 2802
- This setter was removed in v5.0.2 when v4 Column App was deleted
- Caused `ReferenceError: setViewMode is not defined`
- App still reset successfully, but threw error and showed error dialog to user

### Root Causes

**Issue 1: Error messages never updated after v5.0.0 refactoring**
- v4 had simple "Cannot reorder" messages
- v5.0.0 redesigned Explorer with All Books/My Library virtual folders
- Error messages weren't updated to explain the new architecture

**Issue 2: `isReadOnlyView` logic too broad**
```javascript
// BEFORE (line 9776):
const isReadOnlyView = selectedFolderId === '__all__' || selectedFolderId === '__library__';
```
This blocked Manual Order in BOTH All Books AND My Library, but:
- All Books: Correct (books can't be manually reordered in aggregate view)
- My Library: Incorrect (folders CAN be reordered, per design at line 10107)

**Issue 3: Incomplete v5.0.2 cleanup**
- v5.0.2 removed viewMode state variable and all references
- But missed one `setViewMode()` call in Reset App function
- Similar pattern to v5.0.7 (setWishlistFilter incomplete removal)

### The Fixes

**alpha.1: Updated error messages**

Book reordering (lines 10500, 10958):
```javascript
// BEFORE:
showToast('Cannot reorder in All Books', e.clientX, e.clientY);

// AFTER:
showToast('Manual ordering not available in All Books and My Library. These views aggregate books from multiple folders. Use column sorting instead.', e.clientX, e.clientY);
```

Folder reordering (lines 10222, 10809):
```javascript
// Split into two cases:
if (selectedFolderId === '__all__') {
    showToast("Folder reordering not available in All Books", e.clientX, e.clientY);
} else {
    showToast("Change sort to Manual Order to reorder folders", e.clientX, e.clientY);
}
```

**alpha.2: Enable Manual Order in My Library**

```javascript
// BEFORE (line 9776):
const isReadOnlyView = selectedFolderId === '__all__' || selectedFolderId === '__library__';
const viewName = selectedFolderId === '__all__' ? 'All Books' :
                selectedFolderId === '__library__' ? 'My Library' : '';
const tooltipText = isReadOnlyView
    ? `${viewName} is a read-only view - no manual ordering`
    : 'Return to Manual Order';

// AFTER:
// v5.0.8 - Only All Books blocks manual ordering (books can't be reordered)
// My Library allows folder reordering in manual mode
const isReadOnlyView = selectedFolderId === '__all__';
const tooltipText = isReadOnlyView
    ? 'All Books is a read-only view - no manual ordering'
    : 'Return to Manual Order';
```

This allows user to click ✕ button to switch to Manual Order in My Library, enabling folder reordering.

**alpha.3: Remove orphaned setViewMode**

```javascript
// BEFORE (line 2802):
setExplorerView('list');
setViewMode('columns'); // Reset to Columns view

// AFTER:
setExplorerView('list');
```

Line 2801 already sets the view mode correctly. The setViewMode call was redundant and broken.

## Lessons Learned

### 1. **Test With Realistic User Scenarios**

The bug was only found because user actually tried to:
1. Go to My Library
2. Try to reorder folders
3. Click ✕ to switch to Manual Order
4. Found it disabled

If testing just checked "folder reordering works in regular folders," this wouldn't be caught.

**Action:** Always test in ALL contexts (All Books, My Library, Inbox, regular folders).

### 2. **Question Disabled UI Elements**

When user said "Removing the sort is disabled and grayed out," the response should have been:
1. Why is this disabled?
2. Is this intentional or a bug?
3. What's the code that's disabling it?

Instead, we accepted it as given and focused on error messages.

**Rule:** Disabled UI is either intentional (needs tooltip explaining why) or a bug. Always investigate.

### 3. **"Read-Only View" Needs Precise Definition**

The term "read-only view" was applied to both All Books and My Library because they're virtual aggregate views. But:
- All Books: TRULY read-only (no manual book ordering, no manual folder ordering)
- My Library: SEMI read-only (no manual book ordering, YES manual folder ordering)

Lumping them together caused the bug.

**Better approach:**
```javascript
const canReorderBooks = selectedFolderId !== '__all__' && selectedFolderId !== '__library__';
const canReorderFolders = selectedFolderId !== '__all__'; // My Library allowed
const canSwitchToManualOrder = canReorderBooks || canReorderFolders;
```

### 4. **v5.0.0 Refactoring Needs Feature Parity Audit**

This is now the **4th v5.0.0 cleanup bug**:
- v5.0.2: viewMode orphaned code
- v5.0.4: Wishlist filter missing from UI
- v5.0.6: Hidden book visual styling missing
- v5.0.7: setWishlistFilter incomplete removal
- v5.0.8: Manual Order disabled in My Library + setViewMode orphaned

**Pattern:** Functional logic preserved, UI/visual elements lost or incorrectly restricted.

**Recommendation:** Comprehensive v4→v5 feature audit (suggested in v5.0.6 post-mortem, still not done).

### 5. **Orphaned Function Call Pattern**

Both v5.0.7 (setWishlistFilter) and v5.0.8 (setViewMode) had same issue:
- State variable removed
- Most references removed
- A few setter calls in reset/utility functions missed

**Prevention checklist:**
```bash
# When removing a state variable, search for:
grep -n "variableName" file.js        # Variable usage
grep -n "setVariableName" file.js     # Setter calls (most reliable pattern)
grep -n "variableName.*=" file.js     # Assignments

# Verify complete removal:
grep -n "variableName" file.js        # Should return: No matches
grep -n "setVariableName" file.js     # Should return: No matches
```

### 6. **Error Messages Should Guide User**

**Bad:** "Cannot reorder in All Books"
- States what's not allowed
- Doesn't explain why
- Doesn't suggest alternative

**Good:** "Manual ordering not available in All Books. This view aggregates books from multiple folders. Use column sorting instead."
- States constraint
- Explains reason
- Suggests what to do instead

Same principle for "Switch to Manual Order" → "Change sort to Manual Order to reorder folders" (more specific action).

### 7. **Design Comments Should Reference Constraints**

Line 10107 comment:
```javascript
// v5.0.0-alpha.88 - Allow folder reordering in My Library (Inbox protected by isDraggable=false)
// v5.0.8 - Folders CAN be reordered in My Library (unlike books), just not in All Books
const canReorderFolders = explorerSort[0].column === 'custom' &&
    selectedFolderId !== '__all__';
```

This comment clearly states the design intent. But line 9776 contradicted it with no comment explaining why. If there had been:
```javascript
// BOTH All Books and My Library are read-only for book ordering
// My Library still allows folder ordering (see line 10107)
const isReadOnlyView = selectedFolderId === '__all__' || selectedFolderId === '__library__';
```

The contradiction would have been obvious during code review.

## Technical Details

**Affected Functions:**

**1. Book Reordering (Lines 10494-10502, 10952-10960):**
- List view and Cover view drag-drop handlers
- Check if in custom sort mode AND not in All Books/My Library
- Show clear error message explaining why manual ordering not available

**2. Folder Reordering (Lines 10216-10225, 10803-10810):**
- List view and Cover view folder drag-drop handlers
- Check `canReorderFolders` (explorerSort === 'custom' AND not All Books)
- Intentionally allows My Library folder reordering
- Split error messages: All Books vs need to switch to Manual Order

**3. Manual Order Switching (Lines 9773-9797):**
- ✕ button to return to Manual Order from sorted mode
- Was disabled in both All Books AND My Library
- Fixed to only disable in All Books
- My Library needs Manual Order enabled to allow folder reordering

**4. Reset App (Lines 2770-2809):**
- Clears all state on File → Reset App
- Was calling setViewMode('columns') after setExplorerView('list')
- setViewMode removed in v5.0.2, causing ReferenceError
- setExplorerView already handles view mode, so setViewMode was redundant even in v4

**State Variable Evolution:**

```javascript
// v4: Two separate views
const [viewMode, setViewMode] = useState('columns'); // 'columns' | 'explorer'
const [explorerView, setExplorerView] = useState('list'); // 'list' | 'cover'

// v5.0.0: Unified Explorer-only
// viewMode removed - app always in Explorer mode
const [explorerView, setExplorerView] = useState('list'); // 'list' | 'cover'

// v5.0.2: viewMode cleanup
// Removed most references, but missed Reset App setter call (line 2802)

// v5.0.8: Final cleanup
// Removed last orphaned setViewMode call
```

**Folder Ordering Logic:**

```javascript
// My Library folder rendering (lines 10089-10097):
if (selectedFolderId === '__library__') {
    const inbox = childFolders.find(f => f.id === '__inbox__');
    const others = childFolders.filter(f => f.id !== '__inbox__');
    // In custom mode, use order from getChildFolders; otherwise sort alphabetically
    const sortedOthers = explorerSort[0].column === 'custom'
        ? others  // Custom order (manual)
        ? [...others].sort((a, b) => dir * a.name.localeCompare(b.name)); // Alphabetical
    sortedFolders = [inbox, ...sortedOthers].filter(Boolean);
}
```

When user switches to Manual Order in My Library:
1. `explorerSort[0].column` becomes `'custom'`
2. Both left pane and right pane show same folder order (from folder tree structure)
3. User can drag-drop to reorder folders in right pane
4. Left pane updates to match (single source of truth)

**canReorderFolders Logic:**

```javascript
// Line 10107-10108:
const canReorderFolders = explorerSort[0].column === 'custom' &&
    selectedFolderId !== '__all__';
const parentForReorder = selectedFolderId === '__library__' ? null : selectedFolderId;
```

This intentionally:
- ✅ Allows folder reordering in My Library when in Manual Order mode
- ✅ Allows folder reordering in regular folders when in Manual Order mode
- ❌ Blocks folder reordering in All Books (aggregate view, no parent)
- ❌ Blocks folder reordering when in sorted mode (not custom)

**Why alpha.2 was necessary:**

The `isReadOnlyView` check blocked the user from switching TO Manual Order in My Library, creating a catch-22:
- "You need Manual Order to reorder folders"
- "But you can't switch to Manual Order"
- "Because this is a read-only view"
- "But it's NOT read-only for folder ordering!"

Fixing `isReadOnlyView` to only check All Books broke the circular dependency.
