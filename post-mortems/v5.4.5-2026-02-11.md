# v5.4.5 Post-Mortem: Group in Book Explorer

**Date:** 2026-02-11
**Version:** v5.4.5 (6 alpha iterations)
**Feature:** Sort-driven Group toggle with collapsible divider rows

---

## What went well

1. **UX discussion before coding** — The initial "Group by Author" dropdown design was functional but the mid-stream conversation about "Group should just be dividers driven by sort" produced a much better design. The toggle approach is simpler, more flexible, and zero-learning-curve.

2. **displayItems pattern** — The flat array approach (headers + books in one `.map()`) eliminated code duplication. The 235-line book `<tr>` exists in one place, not two.

3. **Sequential scan > Map+sort** — Iterating sorted books and inserting dividers at transitions preserves the user's sort order. The original Map approach re-sorted groups alphabetically, which would have broken rating DESC (showing 1 Star before 5 Stars).

---

## What went poorly

1. **Two syntax errors in a row (alpha.3, alpha.4)** — The table view has a complex nesting structure: outer IIFE → `<table>` → inner IIFE. When I replaced the inner IIFE's rendering code, I lost:
   - The `}` closing the JSX expression `{(() => { ... })()}`
   - The `);` and `})()` closing the outer IIFE's return

   Both were in the original code but I didn't trace the full nesting before editing. **Cost: 2 extra alpha cycles.**

2. **Design iteration after implementation** — Phases 1-5 were implemented with the dropdown/Author-only design, then reworked to the toggle/sort-driven design. The rework was clean (net -13 lines), but the original implementation effort was partially wasted.

---

## Lessons learned

1. **Trace JSX nesting boundaries before editing** — For deeply nested IIFE-in-ternary-in-IIFE structures, write down the complete nesting chain (what opens, what closes) before touching closings. A 5-minute trace would have saved 2 alpha cycles.

2. **Discuss the UX model before the implementation model** — The "dividers driven by sort" insight came from the user seeing the first implementation and realizing the mental model was wrong. Earlier prototyping of the UX concept (even just describing how it would feel to use) could have caught this before code was written.

3. **`getGroupLabel()` as a shared helper was the right call** — Used in 3 places (table displayItems, cover displayItems, Collapse All). Would have been worse to inline in each.

## Design evolution

| Aspect | v1 (alpha.1-4) | v2 (alpha.5-6, released) |
|--------|----------------|--------------------------|
| UI control | Dropdown: None / Author | Toggle button: Group on/off |
| Group key | Fixed to "author" | Mirrors current sort column |
| Group ordering | Map + alphabetical sort | Sequential scan (preserves sort order) |
| Available groups | Author only | Author, Series, Rating, Date, Price, etc. |
| Sort interaction | Separate from sort | Unified with sort |
| Toolbar | "Group: Author ▼" dropdown | "Group" / "Grouped" toggle + ▾▸ chevrons |
