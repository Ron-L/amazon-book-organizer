# v4.24.2 Post-Mortem - Save Gesture Fix for Additional Fetchers

**Release Date:** 2026-01-24
**Duration:** ~25 minutes (fix + test + release)

## What Was Fixed

Applied the same user gesture fix from v4.24.1 (library-fetcher) to 3 additional fetchers:
- amazon-wishlist-fetcher.js v1.4.1
- series-page-fetcher.js v1.1.1
- author-bibliography-fetcher.js v1.0.1

## Root Cause

Same as v4.24.1 - `createWritable()` on FileSystemFileHandle requires an active user gesture that expires during long operations.

## Technical Implementation

### Changes Per Fetcher (~80 lines each)

1. **Added `showSaveButton()` function to progressUI** - Same UI as library-fetcher
2. **Updated return statement** to export the new function
3. **Wrapped fileHandle branch** with showSaveButton call + try/catch

### Bug Found During Testing

Initial implementation used `existingData.books.length` but these fetchers use nested structure `existingData.books.items.length`. Fixed in v1.x.1.b iteration.

## Files Changed

- `amazon-wishlist-fetcher.js` v1.4.1 (+80 lines)
- `series-page-fetcher.js` v1.1.1 (+80 lines)
- `author-bibliography-fetcher.js` v1.0.1 (+80 lines)

## What Went Well

1. **Pattern reuse** - Same fix as library-fetcher, straightforward to apply
2. **Audit revealed all affected files** - Found 3 fetchers with same issue before users reported
3. **Test caught bug** - `books.items` vs `books` structure difference caught before release

## Lessons Learned

1. **Check data structures** - Don't assume all fetchers use same object structure
2. **Proactive auditing** - When fixing a bug in one file, check similar files for same issue
3. **Test the actual code** - Even "mechanical" changes can have subtle differences
