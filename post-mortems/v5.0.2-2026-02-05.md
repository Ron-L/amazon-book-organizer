**Date:** 2026-02-05

## What Happened

### The Problem

v5.0.1 changed `useState('explorer')` default but didn't account for localStorage persistence. Users with `viewMode: 'columns'` saved from earlier sessions would override the default and still load v4 Column App.

### Root Cause

**localStorage persistence trumps useState defaults.** The app loads Explorer settings from localStorage on mount:

```javascript
const savedExplorer = localStorage.getItem(EXPLORER_KEY);
if (savedExplorer) {
    const explorerData = JSON.parse(savedExplorer);
    if (explorerData.viewMode) setViewMode(explorerData.viewMode); // ← This overwrote useState default
}
```

Even though v5.0.1 set `useState('explorer')`, any user with `viewMode: 'columns'` in localStorage would immediately be switched back to Column App on load.

### The Fix

Complete removal of viewMode:
1. **Deleted state variable:** `const [viewMode, setViewMode] = useState('explorer');`
2. **Removed keyboard shortcut guards:** 6 shortcuts had `viewMode === 'explorer' &&` checks
3. **Deleted v4 rendering block:** Entire Column App JSX (~470 lines, lines 8780-9248)
4. **Removed conditional wrapper:** Explorer JSX now renders unconditionally
5. **Cleaned localStorage persistence:** Removed viewMode from save/load/backup/restore

**Result:** App structure simplified. No more conditional rendering. Explorer is the only mode.

## Lessons Learned

### 1. **localStorage Always Wins Over useState Defaults**

When testing state changes, always verify localStorage persistence:
```javascript
// Add this to test plan for any useState default changes:
localStorage.setItem('key', JSON.stringify({ stateVar: 'unexpected-value' }));
location.reload(); // Verify app handles gracefully
```

### 2. **Quick Fix vs Full Fix Trade-offs**

User correctly identified that removing viewMode was faster than full v4 cleanup:
- **v5.0.2 (chosen):** Remove viewMode only → 50 minutes
- **v5.1.0 (deferred):** Full v4 code removal (Steps 4-5 of V4-REMOVAL-PLAN.md) → 2-3 hours

For production issues, choose minimum viable fix + thorough testing over perfect solution.

### 3. **Bash Tools for Large Code Deletions**

When deleting 400+ lines:
- **Edit tool:** Struggled with multiple attempts, left orphaned code
- **sed command:** `sed -i '8780,9248d' file.js` → worked perfectly in one shot

For large structural changes, prefer shell tools over incremental edits.

### 4. **Test Scripts Need Validation Too**

Gave user test JS with wrong localStorage key. In future:
- Grep actual code for key names before providing test scripts
- Or ask user to verify key name first

### 5. **Alpha Iterations Before Release**

CLAUDE.md versioning worked well:
1. Commit as `-alpha.1`
2. Test thoroughly
3. If passing, release as final version

This caught no issues (tests passed first try), but process is sound.
