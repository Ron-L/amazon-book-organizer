1. **Importing backup files** (especially pre-v5.0.5 backups)
2. **Clicking "Clear Filters" button**

### Root Cause

**v5.0.5 incomplete cleanup of wishlistFilter removal.**

v5.0.5 removed 23 references to wishlistFilter but **missed 3 setter calls** in reset/clear functions:

1. **Line 2774** - Reset All Data function:
   ```javascript

   setRatingFilter('');
   setWishlistFilter(''); // ❌ Missed

   ```

2. **Line 3289** - Load library function (called on import):
   ```javascript
   // Reset all filters when loading new library
   setSearchTerm('');
   setReadStatusFilter('');
   setCollectionFilter('');
   setRatingFilter('');
   setWishlistFilter(''); // ❌ Missed
   setOwnershipFilter('');
   ```

3. **Line 7551** - Clear Filters button onClick:
   ```javascript
   onClick={() => {
       setSearchTerm('');
       setReadStatusFilter('');
       setCollectionFilter('');
       setRatingFilter('');
       setWishlistFilter(''); // ❌ Missed
   ```

**Why were these missed in v5.0.5?**

v5.0.5 post-mortem documented removing "23 references" to wishlistFilter. The grep search likely focused on:
- State variable declaration

But these 3 setter calls were in **reset/clear utility functions** that may not have appeared in the initial grep results or were in a different code section.

### The Fix

**Removed all 3 `setWishlistFilter('')` calls:**

1. Line 2774: Reset All Data function

All three were simple one-line removals from lists of filter setters.

## Lessons Learned

### 1. **Complete Removal Checklist for State Variables**

When removing a React state variable, follow this checklist:

**Step 1: Identify all references**
```bash
# Search for variable name
grep -n "wishlistFilter" readerwrangler.js

# Search for setter function
grep -n "setWishlistFilter" readerwrangler.js
```

**Step 2: Remove by category**
- [ ] State declaration: `const [wishlistFilter, setWishlistFilter] = useState('')`
- [ ] Direct usage in logic: `if (wishlistFilter === 'owned')`
- [ ] Setter calls: `setWishlistFilter('value')`
- [ ] localStorage: `localStorage.getItem('wishlistFilter')`
- [ ] useEffect dependencies: `[..., wishlistFilter]`
- [ ] Function parameters: `function foo(wishlistFilter)`
- [ ] Comments mentioning the variable

**Step 3: Verify complete removal**
```bash
grep -n "wishlistFilter" readerwrangler.js
grep -n "setWishlistFilter" readerwrangler.js
# Both should return: No matches found
```

**Step 4: Test all affected operations**
- [ ] Import backup file (old and new)
- [ ] Export backup file
- [ ] Clear filters button
- [ ] Reset all data
- [ ] Filter functionality still works

### 2. **Count References Before and After**

v5.0.5 claimed "23 references removed" but actually there were 26.

Better approach:
```bash
# Before removal
grep -n "wishlistFilter" readerwrangler.js | wc -l
# Output: 26

# After removal
grep -n "wishlistFilter" readerwrangler.js | wc -l
# Output: 0 ✅

# Or output: 3 ❌ (means we missed some)
```

If counts don't match expectations, investigate further.

### 3. **Test Import/Restore After Schema Changes**

Any change that removes fields from localStorage/backup schema needs explicit testing:

**Test matrix:**
- [ ] Import backup from **before** the change (v5.0.4 backup)
- [ ] Import backup from **after** the change (v5.0.5+ backup)
- [ ] Export new backup and verify schema
- [ ] Restore from localStorage (after page refresh)

Missing this testing in v5.0.5 meant the bug wasn't discovered until production.

### 4. **Grep Patterns Should Be Comprehensive**

v5.0.5 grep patterns likely focused on:
```bash
grep -n "wishlistFilter" readerwrangler.js
```

But should have also explicitly searched:
```bash
grep -n "setWishlistFilter" readerwrangler.js  # Setter function
grep -n "wishlistFilter.*=" readerwrangler.js   # Assignments
grep -n "wishlistFilter[,)]" readerwrangler.js  # Function params/calls
```

The setter function name is often the most reliable pattern because it's unique.

### 5. **Document What You Removed**

v5.0.5 post-mortem listed categories removed but not specific line numbers or counts per category. Better documentation:

```markdown

- Filter logic (4): lines 446-449, 6098-6101
```

## Technical Details

**Affected Functions:**

1. **Reset All Data** (line ~2760):
   - Clears localStorage, IndexedDB, resets all state
   - Called when user wants to start fresh
   - Sets all filters to empty string/default values

2. **Load Library** (line ~3280):
   - Called when importing new library from JSON
   - Resets all filters to defaults before loading
   - Ensures no stale filters from previous library

3. **Clear Filters Button** (line ~7547):
   - User-visible button in filter bar
   - Resets all active filters to defaults
   - Most frequently used of the three functions

**Error Stack Trace:**
```
ReferenceError: setWishlistFilter is not defined
    at onClick (readerwrangler.js:7551)
    at HTMLButtonElement.click
```

**Why Import Was Affected:**
The "Load Library" function (line 3289) is called during backup import to reset filters. This is the most critical path because:
- Old backups may contain `wishlistFilter` in saved state
- Import process tries to restore that state
- But even if backup doesn't contain it, the function still calls `setWishlistFilter('')` to reset
- This setter call fails because the function no longer exists

**Why This Broke in v5.0.5:**
React state variables create both:
- A getter: `wishlistFilter` (the value)
- A setter: `setWishlistFilter` (the function to update it)

When you remove the state declaration:
```javascript
// v5.0.4: This line existed
const [wishlistFilter, setWishlistFilter] = useState('');

// v5.0.5: Line removed entirely
// (both wishlistFilter and setWishlistFilter no longer exist)
```

Any code still calling `setWishlistFilter()` will throw `ReferenceError`.

**Grep Pattern That Would Have Caught This:**
```bash
# This would have found all 3 missed references:
grep -n "setWishlistFilter" readerwrangler.js

# Output would have been:
2774:                    setWishlistFilter('');
3289:                setWishlistFilter('');
7551:                                    setWishlistFilter('');
```

v5.0.5 likely only searched for `wishlistFilter` (without "set" prefix), which would show the variable usage but not explicit setter calls in these reset functions.
