# Post-Mortem: 7.0.0 — Corruption-Proof Relay Sync (Relay Write Redesign, Phase 1)

**Date**: 2026-08-17
**Released**: prod + dev (`ee70101`, clean fast-forward; worker deployed to prod first)
**Span**: 2026-08-12 (design discussion) → 2026-08-17 (release) on `feature/relay-write-redesign`
**Scale**: 19 files, +2,505/−431; app 7.0.0, all 5 fetchers major-bumped, nav-hub v2.0.0, worker + client + harness

The arc: Ron hit a live "checksum mismatch" corruption (tab closed mid-wishlist-add tore the relay's in-place multi-key write). Five days later the entire sync layer is rebuilt around atomic generational commits and mailbox letters, with the original failure structurally impossible.

---

## ✅ What worked well

1. **Design-first, and the external adversarial review.** The design doc was written self-contained and epistemically tagged (`[verified in code]` / `[proposed]` / `[assumption]`), then attacked by a fresh Fable 5 thread with no context. The review found **2 correctness-critical flaws** in v1 — the scalar watermark (out-of-order run completion silently discards a whole fetch, *no concurrency needed*) and app-direct canonical writes (the resurrection race falsified v1's own no-lost-data claim). Both were cheap to fix on paper and would have been expensive after code. The review also *deleted* machinery (advisory DO job, quota tiers, volume triggers) — the best kind of finding. **Verdict: the review cycle paid for itself several times over; do it again for anything this load-bearing.**

2. **The harness earned its keep repeatedly.** `relay/test-phase1.mjs` runs the *real* client files in Node against the real dev worker and deliberately recreates the failure scenarios. It caught **three real bugs** before any live testing: the GC keep-2 sweep not counting the just-committed generation (list lag), an undefined `LETTER_TTL` in the client, and — the big one — the worker's **rate-limit counter tripping Cloudflare's ~1-write/sec-per-key limit** and 500ing real writes on any rapid multi-letter run. That last one would have broken the first real full fetch.

3. **Environment isolation, end to end.** Phase 0 (dev worker + dev KV) meant every test — scripted and live — ran against an isolated universe. The nav-hub and app now *automatically* route non-PROD builds to the dev worker, so this safety is permanent, not a one-off. Prod relay data was never touched during five days of destructive testing.

4. **Seed-via-restore.** Restoring a backup into the localhost app pushed a reset run + canonical to the dev relay — simultaneously (a) live-testing the new restore path, (b) seeding the canonical so the library fetch ran incremental instead of an hours-long cold fetch. One stone, three birds.

5. **Live testing found real UX truths cheaply.** The ~60s KV list-propagation window surfaced immediately (add → import "up to date" → confusion). Result: honest toast copy ("No new books found"), a USER-MANUAL item, and the tombstone-aware dedup fix so delete→re-add works without an intervening import.

## ❌ What went wrong

1. **The step-5 fetcher sweep missed two fetchers.** The plan said "3 fetchers"; the codebase has **5** relay writers (series-page + author-bibliography). Caught *before* declaring done by re-running the enumerate-ALL-call-sites grep — the exact [[feedback_investigate_completely]] lesson, this time self-applied in the same session instead of Ron surfacing it. Improvement over the 6.17 pattern, but the plan itself should have been built from the grep, not from memory.

2. **A scripted edit truncated `series-page-fetcher.js` to 0 bytes.** A Python heredoc write failed mid-write (unicode escape issue) after opening the file with `'w'`. Restored from git in seconds — but only because the file was committed. Fix adopted on the spot: **write-to-temp + atomic replace** for all scripted file surgery (the commit pattern, practiced on ourselves). Rule going forward: never open a tracked file `'w'` in a script that can throw mid-write.

3. **A wrong theory, stated too confidently.** The "undone org" after Ron's first restore got a tidy "stale localhost origin" explanation — demolished by one fact (Ron works *solely* in localhost). Retracted next message. The honest end-state: regression was real, pre-dated the restore (second round-trip was clean), cause unknown, not logged per Ron (unreproducible = not actionable). [[feedback_verify_dont_assume]] applies to *diagnosis* as much as to design.

4. **Two "bugs" that were expectations, not defects** — the "why incremental not full fetch?" (the restore had seeded the canonical, per plan) and the collections readStatus-vs-Read-collection cockpit error. Cost: modest. Benefit: the diagnostic added for the second (`window._RW_LAST_COLLECTIONS`) is now a permanent API-vs-app triage tool, and the "cockpit error" run live-verified the entire collections pipeline.

## 🔧 Process notes

- **Worker-first deploys work.** New endpoints are additive; the prod worker shipped before any client and old clients never noticed. Same pattern next time.
- **App + fetchers must ship together** in this design (letters are invisible to an old app). They did; the bookmarklet's load-on-click architecture made fetcher rollout automatic.
- **The stale cache-buster catch** (`relay-client.js?v=6.9.0` in the html) came from *reading the live test's console output*, not from any checklist. Added to release checklist: script-include busters must be audited whenever a shared JS file changes.
- **Majors across the board** (Ron's call): the app/fetcher format incompatibility is exactly what major versions are for; 6.19.0 would have understated it.
- **KV facts that shaped everything** (worth remembering): per-value atomicity but no cross-key ordering; ~60s list propagation; ~1 write/sec **per key**; quotas (writes/lists/deletes/storage) are **per-account, shared across all users**.

## Final thought

The pattern that made this release different: **every claim got checked by something that couldn't be sweet-talked** — the design by a cold adversarial reviewer, the code by a harness that manufactures disasters, the deploy by an isolated environment, and my own explanations by Ron's facts. The two serious design flaws, the three harness catches, and one retracted theory are all cases where the check beat the confidence. Keep the checks.
