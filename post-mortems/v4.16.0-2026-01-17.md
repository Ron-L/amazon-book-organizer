# Post-Mortem: v4.16.0 - Cut/Copy/Paste for Books

**Release Date:** 2026-01-17
**Feature:** Cut/Copy/Paste operations with book copies support

---

## What Was Built

### Core Features
- **Clipboard operations**: Ctrl+X (cut), Ctrl+C (copy), Ctrl+V (paste), Escape (cancel)
- **Book copies**: Same book can appear in multiple columns via Ctrl+C or Ctrl+Drag
- **Delete key**: DEL removes selected books with last-copy protection
- **Enhanced context menu**: Move to/Copy to submenus, clipboard shortcuts displayed

### Supporting Features
- Per-instance hidden state (hide one copy without hiding others)
- GUID-based book entries for unique instance tracking
- Book count shows unique books + copies: "2344 (+1 copy) books"
- Toast notifications for paste feedback
- Footer status showing clipboard state

## Technical Decisions

### GUID-Based Entries
- **Decision**: Column entries changed from plain bookId strings to `{instanceId, bookId}` objects
- **Rationale**: Required for per-instance hidden state and distinguishing copies
- **Trade-off**: Backward compatibility with legacy string entries required throughout codebase
- **Pattern**: `getBookIdFromEntry(entry)` handles both formats; `getInstanceId(entry)` returns null for legacy

### Hidden State Storage
- **GUID entries**: Use `hiddenInstances` Set (stores instanceId)
- **Legacy entries**: Use `book.isHidden` field on book object
- **Pattern**: Check both: `instanceId ? hiddenInstances.has(instanceId) : book.isHidden`

### Copy Creates New GUID
- **Decision**: Copy operations (Ctrl+C, Ctrl+Drag, "Copy to") create new instanceId
- **Move operations** (Ctrl+X, drag, "Move to") preserve original instanceId
- **Rationale**: Copies are independent instances; moves are relocations

## Bugs Encountered & Fixed

### Critical Bugs
1. **Duplicate book removal on drag** (v4.16.0.ad-af): Moving one copy removed all copies
   - Cause: Index lookup used bookId instead of instanceId
   - Fix: Use `findIndex` with GUID matching

2. **Undo/Redo broken** (v4.16.0.aj-ak): GUID entries not restored correctly
   - Cause: Undo snapshot comparison was shallow
   - Fix: Deep comparison for GUID objects

3. **Hidden state not copying for legacy entries** (v4.16.0.be): Only checked hiddenInstances
   - Cause: Legacy entries have no instanceId, use book.isHidden instead
   - Fix: Capture isHidden at copy time using dual-check pattern

### UI Bugs
4. **Book count inverted** (v4.16.0.bg): "Showing: 1 (+2343 copies)" instead of correct values
   - Cause: `filteredBooks()` returns enriched objects with `.id`, not raw entries with `.bookId`
   - Fix: Use `book.id` for filtered results, `getBookIdFromEntry()` for raw entries

5. **Collapsed filter missing copy count** (v4.16.0.bi-bj): Only expanded view showed copies
   - Cause: Two separate display locations
   - Fix: Applied same copy calculation to collapsed view

## What Went Well

1. **Phased approach**: Breaking into small testable phases caught bugs early
2. **Version letter system**: Easy to identify when bugs were introduced
3. **Commit-before-test discipline**: Made bisecting possible when needed
4. **Backward compatibility**: Legacy entries still work without migration

---

## What Could Be Improved

1. **Early GUID adoption**: Should have added GUID entries earlier in app history
2. **Test coverage**: Manual testing caught bugs but automated tests would help
3. **Code organization**: Clipboard logic is scattered; could benefit from extraction
4. **Over-engineered instance IDs**: Used full GUID (`crypto.randomUUID()`) with UUID v4 fallback when a simple timestamp-based LUID (Locally Unique Identifier) would suffice. `Date.now().toString()` would have been adequate for local-only uniqueness with no cross-device sync requirements

---

## Lessons Learned

1. **Dual data formats require exhaustive audits**: When supporting both GUID and legacy entries, every code path that checks one format must check both
2. **enriched vs raw objects**: Functions that return "enriched" objects (with additional computed properties) can't be treated the same as raw data structures
3. **Per-instance state requires instance identity**: Hidden state per-copy requires GUID; can't achieve with just bookId

---

## Future Considerations

1. **Migration to all-GUID**: Could simplify code by converting all legacy entries on load
2. **Clipboard to system clipboard**: Could enable cross-tab copy/paste
3. **Bulk operations**: Ctrl+A + Ctrl+X could enable quick column reorganization
