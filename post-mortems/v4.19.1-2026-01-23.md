# v4.19.1 Post-Mortem - Divider Selection Fix

**Release Date:** 2026-01-23
**Duration:** ~30 minutes (investigation + fix)

## What Was Fixed

### Divider Selection Broken Since v4.16.0
- Clicking a divider didn't visually select the books underneath
- Shift+click after clicking divider didn't work for range selection
- Range selection (Shift+click) excluded dividers
- Ctrl+A excluded dividers

## Root Cause

In v4.16.0, selection was changed from bare book IDs to composite keys (`columnId:bookId:index`) to support selecting individual book instances (same book appearing multiple times in a column).

**However**, `selectDividerGroup` was never updated - it still stored bare book IDs:
```javascript
// OLD (broken)
booksInGroup.push(item);  // Just "B001234567"
setSelectedBooks(new Set(booksInGroup));

// NEW (fixed)
selectionKeys.push(`${columnId}:${bookId}:${i}`);  // "col1:B001234567:5"
```

Since all selection checks used composite keys, the bare IDs never matched.

## Technical Changes

1. **`selectDividerGroup`** - Build composite keys for books, add divider with special key format (`columnId:divider:dividerId:index`), set `lastClickedBook` anchor

2. **`selectBookRange`** - Simplified to use raw indices, include dividers with special key format

3. **Ctrl+A handler** - Include dividers with special key format

4. **Divider visual** - Check both `selectedDivider` AND `selectedBooks` for highlight

## UX Discussion

Before fixing, discussed with user whether dividers should be included in selection:

**Principle adopted:** "Explicit selection should be inclusive. Shortcuts can be selective."
- Ctrl+A, Shift+click = explicit selection → include everything
- Click divider = shortcut → select logical group (divider + its books)

The old behavior inverted this - shortcuts were inclusive but explicit selection was exclusive.

## Files Changed

- `readerwrangler.js` v4.19.1

## Lessons Learned

1. **Feature flags need full audit** - When changing a core pattern (like selection key format), all usages must be updated together
2. **User-reported bugs often reveal design gaps** - User's frustration led to UX improvement (inclusive vs exclusive selection)
3. **Separate file versions help** - ORGANIZER_VERSION (file) vs APP_VERSION (release) made the bug traceable to v4.16.0
