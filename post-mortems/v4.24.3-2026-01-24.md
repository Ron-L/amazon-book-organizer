# v4.24.3 Post-Mortem - Wishlist Duplicate Detection

**Release Date:** 2026-01-24
**Duration:** ~10 minutes (fix + test + release)

## What Was Fixed

Wishlist fetcher was adding books to library without checking if they already existed, causing duplicates in the JSON file.

## Root Cause

Comment at line 13 stated: "no duplicate check - App Loader handles"

While the App Loader does deduplicate when loading the JSON file, the file itself accumulated duplicates over time. This was a design decision that proved problematic - users expected the fetcher to detect duplicates at add time.

## Technical Implementation

### Changes (amazon-wishlist-fetcher.js v1.4.2)

Added duplicate check before adding book (lines 823-840):

```javascript
// Check for duplicate
console.log('[4] Checking for duplicates...');
const existingBook = existingData.books.items.find(b => b.asin === book.asin);

if (existingBook) {
    // Book already in library
    console.log(`   ⚠️ Book already in library: "${book.title}" (ASIN: ${book.asin})\n`);
    progressUI.showError(`<strong>${book.title}</strong><br>is already in your library`);
    new Image().src = 'https://readerwrangler.goatcounter.com/count?p=/event/wishlist-duplicate-skipped';
    return;
}
```

### Other Changes
- Updated header comment flow steps (5-8) to reflect duplicate checking
- Added GoatCounter event `wishlist-duplicate-skipped` for analytics

## Files Changed

- `amazon-wishlist-fetcher.js` v1.4.1 → v1.4.2 (+22 lines)

## What Went Well

1. **Quick diagnosis** - Bug reported with clear reproduction case (Old Man's War ASIN)
2. **Simple fix** - Just needed to add `.find()` check before `.unshift()`
3. **Minimal code change** - ~22 lines added

## Lessons Learned

1. **Deduplication at write time** - Better to prevent duplicates at source than rely on load-time cleanup
2. **File growth** - JSON files should not grow unbounded due to duplicate entries
3. **User expectations** - Users expect "add to wishlist" to detect if item already exists
