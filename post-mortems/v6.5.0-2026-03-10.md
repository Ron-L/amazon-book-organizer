## 🎯 What Worked Well

### 1. **UX Expert Hat for Tooltip Copy**
- User proposed rough copy for system tooltips; Claude evaluated and refined each one
- The "All Books" tooltip debate (should it mention "view"?) resolved by focusing on *behavior* ("you can't move books out of here") rather than technical label ("this is a view") — more useful to users who don't know the app's internal vocabulary
- **Lesson**: Tooltip copy should describe behavior and affordances, not technical category labels. "You can't do X from here — use Y instead" is more useful than "this is a [type]."

### 2. **False Affordance Caught Before Shipping**
- The original Folders tooltip said "move books here" — user correctly identified that "here" implies the Folders section *label* is a drop target, which it isn't
- Fix: "drag books into any folder below" — "below" gives spatial context, "any folder" clarifies individual folders are targets
- **Lesson**: Spatial deictic words ("here", "this") in tooltips on non-interactive labels are false affordances. Prefer directional words ("below", "above") or structural words ("any folder within") that point past the label to the actual targets.

### 3. **Views and Folders Tooltips Already Existed**
- When adding system tooltips, Views and Folders already had `title` attributes from v6.4.0 — only All Books, Inbox, and Trash needed adding
- No duplication or overwriting risk
- **Lesson**: Check before assuming — existing code may already handle part of a feature.

### 4. **Parallel Alpha Commits per Concern**
- alpha.1: Description field in Properties dialogs
- alpha.2: System tooltips for All Books, Inbox, Trash
- alpha.3: Folders tooltip copy fix
- Each concern isolated for clean bisection if needed

## ❌ Mistakes Made

### 1. **"Move books here" on a Non-Droppable Label**
- The Folders section header tooltip (written in v6.4.0) said "move books here to arrange your library"
- "Here" on a label that cannot receive drops is a false affordance — users might try dragging to the Folders label itself
- User caught this before release
- **Fix**: "drag books into any folder below" — directional and target-specific
- **Why it happened**: The tooltip was written thinking about the *concept* (the Folders area) rather than the *interaction* (individual folder rows below the label)

## 📚 Lessons Learned

### 1. **Tooltip Copy Checklist for Section Headers**
When writing a tooltip for a section header/label that is NOT itself a drop target:
- ❌ Don't use "here" — implies the label is the target
- ❌ Don't use "this" — same problem
- ✅ Use "below", "within", "any [item] below" — spatial, points past the label
- ✅ Describe what users *do* with the children, not the parent label

### 2. **Behavior Over Category in Tooltips**
- "This is a view, not a folder" is technically correct but requires the user to know what "view" means in the app
- "You can't move books out of here — use folders to arrange them" requires no prior knowledge
- **Rule**: Write tooltips for a user encountering the UI for the first time, not a user who already understands the architecture

### 3. **Agency Framing for Inbox**
- "This is where ReaderWrangler puts newly imported books" correctly attributes agency to the app, not the user
- Users didn't put books there — the app did. This framing sets correct expectations and explains why books appear there automatically
- **Rule**: When a system action places content somewhere automatically, the tooltip should name the actor ("ReaderWrangler puts...") not use passive voice ("books appear here")

## 💡 Recommendations for Future

### 1. **Audit All Tooltips on Non-Droppable Labels Before Release**
- Any `title` on a section header or label that cannot receive drops should be reviewed for "here"/"this" usage
- Quick grep: `title=.*here` on elements that have no `onDrop` handler

### 2. **Tooltip Review Pass as Part of Release Checklist**
- When adding or modifying tooltips, read each one aloud imagining a first-time user
- Ask: does this describe what I *do* or what this *is*? (prefer *do*)
- Ask: does "here" or "this" imply interactivity that doesn't exist?
