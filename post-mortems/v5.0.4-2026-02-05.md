## What Happened

### The Problem

After v5.0.0 menu/toolbar redesign, users could not filter to see only wishlist books. The Source dropdown only showed:
- Purchased, Sample, Borrowed, Prime, Kindle Unlimited, KOLL, Comixology

But not:
- **Wishlist** ❌

This meant wishlist books were effectively hidden unless user scrolled through entire library or searched by title.

### Root Cause

**v4 interface had TWO separate filters:**
1. **Wishlist filter** (❤️): All Books | Owned Only | Wishlist Only
2. **Ownership Type filter** (🏷️): All Types | Purchased | Sample | etc.

**v5.0.0 redesign consolidated filters** into toolbar dropdowns but only migrated the ownership types. The wishlist filter UI was lost.

**Why was it separate in v4?**
- Historical: `onWishlist` was a boolean flag, `ownershipType` was an enum
- Data model: Books could theoretically be `onWishlist=true` with `ownershipType='purchased'` (legacy data)

**Why consolidate in v5?**
- UX: Simpler mental model (Source = where book came from)
- Data: `ownershipType: 'wishlist'` exists in current fetcher
- Logic: Wishlist and owned are mutually exclusive categories

### The Fix

**1. Added 'wishlist' to Source dropdown** (first in list, before Purchased)

**2. Updated filter logic** to check BOTH fields for backward compatibility:
```javascript
const matchesOwnership = !ownershipFilter ||
    (ownershipFilter === 'wishlist'
        ? (book.onWishlist || book.ownershipType === 'wishlist')  // Either field
        : (book.ownershipType || 'purchased') === ownershipFilter);
```

This handles:
- **New wishlist books**: `ownershipType: 'wishlist'` ✅
- **Legacy wishlist books**: `onWishlist: true` (even if ownershipType is different) ✅
- **Owned books**: `ownershipType: 'purchased'|'sample'|etc.` ✅

**3. Updated DATA-SCHEMA.md** to document:
- `ownershipType` enum now includes `wishlist`
- `onWishlist` field explained
- Backward compatibility note

## Lessons Learned

### 1. **Feature Parity Checklist for UI Redesigns**

When doing major UI restructuring (like v5.0.0), create explicit checklist:
- [ ] List all filters in old UI
- [ ] Map to new UI locations
- [ ] Verify each filter works in new UI
- [ ] Test with realistic data

Example for v5.0.0:
- v4 filters: Search, Read Status, Collections, **Wishlist**, Ownership Type, Series, Date Range, Tags, Ratings
- v5 filters: ✅ Search, ✅ Read Status, ✅ Tags, ✅ Source (ownership), ❌ **Wishlist**

### 2. **Consolidate Related Filters with Backward Compatibility**

When merging separate filters into one:
- **Identify data model**: Is there one source of truth or multiple?
- **Check legacy data**: Do old formats need special handling?
- **Dual-field checking**: Filter against ALL relevant fields

In this case:
- `onWishlist` (boolean) was legacy
- `ownershipType: 'wishlist'` is current
- Filter checks BOTH for full coverage

### 3. **Keep Schema Documentation Current**

DATA-SCHEMA.md was created to prevent field name mismatches, but ownershipType enum was incomplete. When adding new enum values to code:
1. Update the enum in code
2. Update DATA-SCHEMA.md immediately
3. Add version history entry

### 4. **Migration Testing with Real Data**

v5.0.0 testing used developer's library but may not have had wishlist books. Test major changes with:
- Empty library (new user)
- Small library (~10 books)
- Large library (2000+ books)
- **Edge cases**: Wishlist-only books, hidden books, books with no covers, etc.

### 5. **Changelog Should Document Breaking Changes**

v5.0.0 CHANGELOG focused on new features but didn't mention:
- "Wishlist filter consolidated into Source dropdown" (if it had been migrated)
- "Column/Explorer mode toggle removed" (viewMode deprecation)

Users expect UI changes to be documented.

## Technical Details

**Old v4 UI Structure:**
```javascript
// Two separate filters
const [wishlistFilter, setWishlistFilter] = useState(''); // '' | 'owned' | 'wishlist'
const [ownershipFilter, setOwnershipFilter] = useState(''); // '' | 'purchased' | 'sample' | ...

// Separate dropdowns in UI
<select value={wishlistFilter}>
  <option value="">All Books</option>
  <option value="owned">Owned Only</option>
  <option value="wishlist">Wishlist Only</option>
</select>

<select value={ownershipFilter}>
  <option value="">All Types</option>
  <option value="purchased">Purchased</option>
  <!-- etc -->
</select>
```

**New v5 UI Structure:**
```javascript
// One consolidated filter
const [ownershipFilter, setOwnershipFilter] = useState(''); // '' | 'wishlist' | 'purchased' | ...

// Single dropdown with all source types
<select value={ownershipFilter}>
  <option value="">All Types</option>
  <option value="wishlist">Wishlist</option>  {/* ← Added in v5.0.4 */}
  <option value="purchased">Purchased</option>
  <!-- etc -->
</select>
```

**Data Model Evolution:**
- **Pre-v4.18**: `isOwned: true/false` (from fetcher)
- **v4.18+**: `onWishlist: true/false` (boolean flag) + `ownershipType: 'purchased'|'sample'|etc.`
- **Current**: `ownershipType: 'wishlist'|'purchased'|etc.` (wishlist is an ownership type)

The dual-field filter ensures all three data formats work correctly.
