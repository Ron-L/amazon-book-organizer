# Post-Mortem: 7.6.0 + 7.6.1 — folder ordering, mobile honesty, and the week the ghosts died

**Date**: 2026-09-01
**Releases**:
- **7.5.1** (2026-09-01, mid-branch detour) — KV orphan sweep: torn-push chunks found and reaped (the 678 MB storage leak); harness self-teardown
- **7.6.0** (2026-09-01) — 25 alphas on `feature/folder-ordering`: pins, Name/Count sorts, bake, placement-honors-mode, mobile order mirror + freshness nudge + honest counts, the guest guard (scrambler kill), the undo-integrity trilogy, series fetcher v2.0.2
- **7.6.1** (2026-09-01, same-day hotfix) — freshness = generation identity, not a timestamp race; both-timestamps banner

Four days (2026-08-29 → 09-01), three releases, three design docs born (MULTI-INSTANCE, CROSS-SECTION-DRAG, the much-amended FOLDER-ORDERING), and the two longest-running ghosts in the project — the folder-order scrambler and the storage creep — both diagnosed to root cause and killed.

---

## ✅ What worked well

1. **Spec-first waves made the building trivial.** Every wave's decisions were ratified on paper before code (pins semantics, placement rules, count definitions, the ordering asymmetry). Waves B/C/D were each answered with "straightforward — no plan needed" and *were*. The expensive part was the deciding, done in discussion where it's cheap; the code was transcription.
2. **Live forensics with the user as instrument.** The scrambler fell to console snippets Ron ran against his own stores (SNAP/CHECK, the KV inventory): quota exonerated by probe, integrity checker exonerated by reading, the real three-layer cause caught red-handed (order stored only as implicit array position × mobile's field-stripping cache write × same-origin last-writer-wins). The fix (guest guard + deny-list) was verified *live in both directions* before we called it dead.
3. **"Write the doc, then check yourself" caught two real holes** — Ron's instinct, twice validated in one feature: the wall-clock stamp misfire and the mobile re-stamp monotonicity bug were both found while writing MULTI-INSTANCE.md, before any code. The doc pass is cheaper than the debug pass it replaces.
4. **One principle unified three fixes**: *an undo entry is invalid when an entity it references ceases to exist.* Permanent delete purges by mention, restore blanks the world, imports purge their removal set — no per-op tables, self-maintaining. Ron's "is there a more fundamental property?" question produced it.
5. **The alpha cadence + the MOBILE_VERSION suffix convention** (born mid-cycle from Ron's "invisible changes + no build marker = guaranteed mystery") paid for itself within days — the installed-PWA hunt and the phone-still-on-1.7.0 confusion were both settled by reading a version string.
6. **User testing found what design didn't — repeatedly.** The sort-control iconography inversion (one session of real use), the pin alignment, menu grouping, the ghost undo, the freshness race on real hardware. Design review caught zero of these; Ron's hands caught all of them.
7. **The GitHub rescue**: with a Pages deploy wedged in an uncancellable queue-limbo on release night, the direct `POST /pages/builds` API built and deployed in ~50s, bypassing Actions entirely. Now a known lever (as is using the locally-stored git credential for API surgery, at Ron's standing invitation).

## ❌ What went wrong

1. **7.6.0 shipped a freshness check that nagged a fully-synced phone forever.** The check compared the *save* stamp against the *push* time — different events, always a debounce apart. The deeper failure: **the dev sim structurally cannot be a synced phone** (the guest guard makes it always-skip, which we'd correctly defined as the pass condition — and that same property made it the blind spot). The first real-hardware session found it in minutes; hotfixed same day as gen-identity comparison. Lesson: *when a test environment's correct behavior is "this path never runs," the path is untested — say so out loud before shipping.*
2. **React #310 in alpha.24** — the freshness `useEffect` placed below `MobileApp`'s conditional early-returns; crash on every load transition. The Babel parse check passes it; hooks rules are structural, not syntactic. TinySuspender — all week a suspect in every mystery — found it within the hour by forcing the exact reload, earning an honest day's pay as a test harness.
3. **The sort-control arc took three alphas** (direction hidden in menu → split control against the iconography → aligned): alpha.16 assigned menu to the ⇅ "reverse" glyph and flip to the key name — exactly inverted from what the symbols promise. Recorded lesson: *symbols make promises the clicks have to keep; a control you can read beats one you must decode.*
4. **The two-mailroom model (localhost→dev, everything-else→prod) bit Ron at least three times** in two days — pairing hunts, "phone won't sync," moved-a-book-on-the-wrong-desktop. The docs exist (MULTI-INSTANCE) and each incident decoded quickly, but the model clearly doesn't stick under fatigue. The server chips help; some future affordance may need to say *which mailroom this change goes to* at the moment of action.
5. **Release-night deploys inherit ignored debt**: the routinely-ignored GitHub Pages failure emails became the release-day root cause. "GitHub will get there eventually" has an exception — the day you need it now.
6. **The restore push carried two stale layers** (pre-restore closure org + pre-restore stamp) found only while verifying an adjacent fix — the TODO's own description was outdated by the time it was implemented. Reading the code beat trusting the ticket.
