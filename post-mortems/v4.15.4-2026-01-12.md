# v4.15.4 Release Post-Mortem (Search Filter Includes Column/Divider Names)

**Date**: 2026-01-12
**Duration**: ~15 minutes (single session)
**Versions Iterated**: 2 letter versions (v4.15.4.a through v4.15.4.b)
**Release Components**:
- readerwrangler.js v4.15.4

---

## What Worked Well

### 1. **Building on v4.15.3 Infrastructure**
- The column/divider hiding from v4.15.3 provided clear extension points
- Just needed to add additional "OR" conditions to existing filter logic
- **Lesson**: Good architectural decisions in previous releases make future enhancements easier

### 2. **User Testing Caught Edge Case**
- Initial implementation only checked column names and divider labels independently
- User testing revealed dividers wouldn't appear if parent column was filtered out
- Quick fix in v4.15.4.b added column-level check for matching divider labels
- **Lesson**: Real-world testing catches integration issues that unit thinking misses

---

## Mistakes Made

### 1. **Incomplete Initial Design**
- Didn't consider that column filter runs before divider filter
- A matching divider label was useless if its column was already hidden
- **Fix**: Added check in column filter for any matching divider labels within the column

---

## Lessons Learned

### 1. **Filter Cascade Order Matters**
- Column visibility is determined first (columns.filter)
- Divider visibility is determined second (inside filteredBooks)
- When adding a feature that spans both levels, must consider the cascade
- The column filter needed to know about divider labels, not just its own name

### 2. **Search vs Other Filters**
- Search applies to names/labels (column name, divider label, book title/author)
- Other filters (read status, collection, rating, etc.) apply only to book attributes
- This distinction was correctly identified during planning and preserved in implementation

## Final Thoughts

Clean enhancement that builds naturally on v4.15.3's filter infrastructure. The cascade issue (column filter runs before divider filter) was a good reminder that when features span multiple layers, each layer may need awareness of the lower layers' criteria.

**Key Takeaway**: When adding filter criteria that apply to nested elements (dividers inside columns), the parent filter must also consider child matches to avoid hiding the parent prematurely.
