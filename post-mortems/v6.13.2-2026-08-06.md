## 🎯 What Worked Well

### 1. **Applied last release's lesson — verified the live path before extending it**
- Before extending the "In" popup to folders/Book Lists, I read the two explorer render sites and *confirmed* what they were: path A (~js14194) is the **list-view `<tr>`**, path B (~js14785) is the **cover** — both fed by the same `displayItems.map` every view uses. So one `bookTipViewOk()` helper at four gates covered every view in both modes.
- **Lesson banked**: `feedback_verify_live_handler` paid off immediately — I checked which code renders where instead of assuming, and the extension was a clean one-pass change.

### 2. **The popup rework landed cleanly once the spec was precise**
- The user's exact spec — "cursor = the inner corner, fill the quadrant away from center, ≥10% overlap, settle before showing" — mapped directly to the alpha.5 implementation (clamp cursor to ≤90% from center; `vUp/hLeft` from cursor-vs-center; room-flip fallbacks). It worked first try and the user called it "perfect."
- **Lesson**: a spec stated in terms of the *invariant* ("always ≥10% overlap," "cursor is the inner corner") translates to code far more directly than a spec stated as symptoms ("it's too high," "I can't reach it").

### 3. **Scoped the returned-borrows feature instead of rushing to build it**

We discussed the approach, agreed the design (flag `activeBorrow===false` → hidden-by-default filter, *not* the exclusion list), wrote `docs/design/RETURNED-BORROWS.md` + a TODO, and **stopped there** — the user explicitly wanted the popup finished first. No scope-bleed into the release.

### 4. **Clean release**

## ❌ Mistakes Made

### 1. **Two cover/row render paths with different indentation — a `replace_all` silently hit only one**
- The onMouseEnter/Move/Leave rewiring lives at two sites with **different indentation**. My `replace_all` (using one site's indentation) reported "all occurrences replaced" but only matched path A; path B still said `=== '__all__'`.
- **What surfaced it**: I re-grepped after the edit and saw path B unchanged — caught before commit.
- **Lesson**: "all occurrences replaced" only means *all that matched the string* — with indentation-sensitive duplicated JSX, **re-grep the invariant after a multi-site edit** rather than trusting the success message. (This is the same duplicated-site class as the alpha.3 second-`setBookTooltip` miss the day before.)

### 2. **Popup positioning took three alphas (3 → 4 → 5) before the right model**
- alpha.3 (extend-away-from-cursor, ~10% overlap) → alpha.4 (fix a missed second render site + horizontal anchor) → alpha.5 (the cursor-corner rework the user actually wanted). The first two were reasonable but were *my* model; the fifth came from the user re-specifying after using it.
- **What should have happened**: less certain here — the user themselves said "upon actually using it, I'd like it different," i.e. the final model emerged from real use, not something I could have specced up front. The honest takeaway is to **ship a rough popup sooner for feel-testing** rather than polishing my own model through two alphas first.

## 📚 Lessons Learned

### 1. **Re-grep the invariant after any duplicated-site edit**
- Duplicated JSX (list path + cover path) has bitten this codebase twice now via indentation/second-site misses. The cheap guard is a post-edit grep for the *old* pattern expecting zero hits — which is exactly what caught path B this time.

### 2. **Invariant-based UX specs implement in one pass**
- "Cursor is the inner corner; ≥10% overlap always" → code. Symptom-based specs ("too high," "can't reach") → iteration. When a UX ask arrives as symptoms, it's worth converting it to an invariant *with the user* before coding.

### 3. **Hover-intent (settle-to-show) is the right default for dense hover targets**
- The single change that made the popup "feel perfect" was not positioning — it was *only showing after the cursor settles*. Movement dissolves + repositions, so scanning a grid never chases a popup. Worth reaching for on any dense hover affordance.
