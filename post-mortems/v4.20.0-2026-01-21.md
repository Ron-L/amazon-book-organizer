# Post-Mortem: v4.20.0

**Date:** 2026-01-21
**Release Type:** Bug Fix

## Summary

Fixed wishlist preservation bug introduced in v4.19.0's schema migration from v2.0 to v2.1. Wishlist books were being saved to IndexedDB but not displayed in UI until page refresh.

## What Changed

### Bug Fixes
1. **Legacy field normalization** - `saveBooksToIndexedDB` now normalizes existing books when checking for orphan wishlists, converting legacy `isWishlist` to `onWishlist`
2. **UI state sync** - `saveBooksToIndexedDB` now returns merged books so `loadLibrary` can update React state immediately

### Schema
- Bumped to v2.1
- Loaders now accept any `2.x` version (forward compatible)

## Root Cause Analysis

The v4.19.0 data model change renamed `isWishlist` → `onWishlist`. Two places weren't updated:

1. **`saveBooksToIndexedDB` line 80-86**: Read existing books from IndexedDB without calling `normalizeBook()`, so books with legacy `isWishlist: true` failed the `existingBook.onWishlist` check at line 100

2. **`loadLibrary` line 1848-1849**: Called `setBooks(processedBooks)` with only books from the imported file, not the merged result including preserved orphan wishlists

## Discovery

User reported: "Wishlist books disappear on import but reappear after page refresh"

This indicated:
- Data was being saved correctly (reappear on refresh)
- UI state wasn't being updated (disappear on import)

## Lessons Learned

1. **Test legacy field migration paths** - When renaming fields, test that all code paths reading from storage normalize legacy formats

2. **Check state synchronization** - When a function modifies data internally, ensure the modified data flows back to UI state

3. **Schema version changes need thorough testing** - The v2.0 → v2.1 transition touched multiple files; each needed verification
