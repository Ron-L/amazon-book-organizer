# Post-Mortem: 7.7.1 + 7.7.2 — two clean releases in one day

**Date**: 2026-09-07
**Releases**: 7.7.1 (Auto-Organize "Already filed" grouped layout) and 7.7.2 (mail-run reclamation
retries on every import), both prod+dev, same Sunday. Zero drama, one alpha each. Short PM by design —
recorded because *why it went well* is worth as much as any failure analysis.

## What shipped

- **7.7.1**: the "Already filed" section groups by home folder (chips + cover-wrap) instead of one
  row per book — built Thursday as 7.7.1-alpha.1, confirmed by Ron same evening, released Sunday.
- **7.7.2**: `readMailbox` reports absorbed-but-still-present runs from its key-listing pass (zero
  added downloads); every import retries `deleteAbsorbedBulkRuns` on them. Kills the one-chance
  weakness where a closed tab stranded ~17MB bulk runs for their full 90-day TTL.

## ✅ What worked well — and why

1. **Precise expected values (Rule 4) at their best.** Before Ron tested, the expected result was
   computed from his live dev data: "expect exactly `🧹 Reclaimed 27 absorbed bulk run(s)`". He got
   exactly 27. Post-verification matched to the key: 352 → 217 (135 = 27 runs × 5 keys). A test whose
   prediction is exact converts one run into total confidence — no "seems fine," no second round.
2. **Instrument → prove → fix → prove-fixed, with REAL debris as the fixture.** Ron's call: don't
   hand-clean the stranded runs, they're the live test case (his instinct also kept prod's 7-run pile
   for the release-day proof). The fix was verified against production-shaped reality, not a synthetic.
3. **The morning KV inventory paid for the afternoon fix.** What began as "is the storage all mine?"
   (channel-by-channel listing, manifests for real byte counts) surfaced the reclamation gap as a
   *diagnosis with evidence* before any code was touched. Investigations that end in inventories keep
   paying: the same saved listing later provided the exact test prediction.
4. **Close-the-parenthesis release discipline.** Morning: the finished-but-unreleased layout fix was
   spotted as an open parenthesis and shipped before new work began. Afternoon: Ron caught the same
   pattern forming again — item 10 was done and proven, so it shipped alone as 7.7.2 rather than
   waiting weeks inside the 7.8.0 batch. Small, proven, self-contained fixes ship now; version numbers
   are cheap.
5. **Continuity across a 3-day gap cost nothing.** Thursday ended with TODO batch items + a memory
   file written for "refresh me Sunday." Sunday opened with zero re-derivation — the KV question was
   answered from the record (7.6.2 PM) rather than recollection, correcting a mis-memory ("we killed
   orphan channels" → actually six dead legacy singles + a fixture, after Ron's own
   are-we-sure-they're-mine challenge).
6. **Existing wrangler OAuth beat token ceremony.** "Option A — try your existing login first" turned
   a walkthrough-and-token exercise into one `whoami`.

## ❌ Small stumbles (recorded, none costly)

1. **PowerShell `Set-Content` injected a BOM** into both HTML files during version bumps — caught in
   the diff (2-line change showed as 20), reverted, redone with the Edit tool. The transport lesson
   (Edit tool for file surgery, never shell text transforms) re-earned in miniature.
2. **wrangler v4 KV commands default to LOCAL simulation** — first listing returned `[]` from the
   nonexistent local store; `--remote` is mandatory. Recorded here so it's never re-diagnosed.
3. **Key counts ≠ bytes.** First read of prod-vs-dev storage ("dev is the bulk") was wrong — prod's
   fewer keys were 17MB chunks. Corrected only after reading manifests for real byte counts. Size
   claims need size data.
4. Transient Cloudflare API 401s (two, both vanished on retry) — noted as ambient noise, not signal.
