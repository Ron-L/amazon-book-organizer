# v4.25.1 Post-Mortem - Ctrl Shortcuts in Modals Fix

**Release Date:** 2026-01-24
**Duration:** ~30 minutes (implementation + testing + iteration)

## What Was Fixed

Ctrl+C, Ctrl+A, and Ctrl+X keyboard shortcuts now work properly in input fields and modals.

## Root Cause

The global keyboard handler in `handleKeyDown` was intercepting Ctrl+A/C/X and calling `e.preventDefault()` to implement app-level shortcuts (select all books, copy books to clipboard), even when the user was focused on an input field or had text selected in a modal.

## Technical Implementation

### Changes (readerwrangler.js v4.21.1)

Added three early-return checks at the top of the keyboard handler (lines 814-829):

1. **Input focus check** (v4.21.1.a):
   ```javascript
   const isInputFocused = ['INPUT', 'TEXTAREA'].includes(document.activeElement?.tagName);
   if (isInputFocused && (e.ctrlKey || e.metaKey) && ['a', 'c', 'x'].includes(e.key)) {
       return; // Let browser handle natively
   }
   ```

2. **Text selection check** (v4.21.1.b):
   ```javascript
   const hasTextSelection = window.getSelection()?.toString().length > 0;
   if (hasTextSelection && (e.ctrlKey || e.metaKey) && e.key === 'c') {
       return; // Let browser copy selected text
   }
   ```

3. **Modal open check for Ctrl+A** (v4.21.1.c):
   ```javascript
   if (modalBookRef.current && (e.ctrlKey || e.metaKey) && e.key === 'a') {
       e.preventDefault(); // Don't select entire page or books
       return;
   }
   ```

## What Went Well

1. **Incremental approach** - Three separate fixes, each committed and tested
2. **Clear problem diagnosis** - Quickly identified the root cause in keyboard handler
3. **User-driven requirements** - User clarified the real use case (copying ASIN, reviews)

## Issues Found During Testing

1. **v4.21.1.a** - Fixed input fields but not selected text in modal
2. **v4.21.1.b** - Letting browser handle Ctrl+A selected entire page, not just modal
3. **v4.21.1.c** - Final fix: disable Ctrl+A entirely when modal open (user can still drag-select)

## Lessons Learned

1. **Global keyboard handlers need escape hatches** - Always check for input focus and text selection before intercepting standard shortcuts.

2. **Browser Ctrl+A is all-or-nothing** - Can't easily scope to a container; better to disable and let user manually select.

3. **User's actual use case matters** - Initial assumption was about input fields; real need was copying ASIN/reviews from non-editable modal content.

## Design Decisions

1. **Ctrl+A disabled in modal** - Better than selecting entire page; user can triple-click or drag-select
2. **Ctrl+C respects text selection** - If text is selected anywhere, copy that instead of books
3. **Input fields always get native behavior** - Input/textarea Ctrl+A/C/X always work natively
