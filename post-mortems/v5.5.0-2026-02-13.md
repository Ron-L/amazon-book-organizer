### 1. **UX expert review before implementation**
- User asked for UX analysis of the TODO task before coding. This surfaced five concrete refinements: dropdown caret for clickability, shift+click discoverability, Custom Order graying, clear-all behavior, and multi-sort display concerns
- Three of these made it into the revised spec; the other two were already handled (column header tooltip existed at line 9089) or didn't need changes (3-key sort cap left as-is)
- **Lesson**: Running a UX review pass on a spec before implementation catches affordance gaps that are cheap to add but expensive to discover post-release

- Feature shipped in one alpha with zero rework. Plan mode identified all touch points: state, click-outside, ESC handler, dependency array, sort display JSX, dropdown items, shift+click logic
- The sort logic was directly reused from the existing column header handler (line 9090-9127) — no new sort algorithm needed
- **Lesson**: When a feature is "purely a UI control" over existing infrastructure, plan mode + pattern reuse = first-try success

### 3. **Existing pattern reuse across all layers**
- Click-outside: `data-sort-picker` attribute + `e.target.closest()` check — 12th dropdown using this pattern

- Dropdown styling: same white/border/shadow/zIndex as Status Filter and all other toolbar dropdowns

- **Lesson**: Consistent patterns across the codebase make new features mechanical to implement

## 📚 Lessons Learned

### 1. **COLUMN_CONFIG is the single source of truth for sort options**
- The dropdown derives its options from `Object.values(COLUMN_CONFIG).filter(c => c.sortKey)` plus a manual "Manual Order" entry
- This means adding a new sortable column in the future automatically adds it to the sort picker — no second touch point
- The sort display label map (the long ternary chain) is a separate concern — it maps sort keys to display names and had a bug (`myRating` missing). Using COLUMN_CONFIG's `.label` property in the dropdown avoids this duplication

### 2. **The sort display label map had a latent bug**
- `myRating` was missing from the ternary chain at line 8818, falling through to raw `s.column` which would display "myRating" instead of "My Rating"
- This bug was invisible because My Rating sorting was rarely used and the raw key name is close enough to the intended label
- Fixed as part of this release by adding the `myRating` case
- **Pattern**: When you have a display label map, cross-check it against the full config to catch missing entries

### 3. **"Leave it as-is" is a valid design decision**
- The 3-key sort cap discussion could have led to a code change (reducing to 2). Instead, analysis showed no downside to leaving it: the code works, the UI doesn't expose it awkwardly, and the rare user who shift+clicks three headers gets correct behavior
- Avoiding unnecessary changes reduces risk and keeps the diff focused

## 💡 Recommendations for Future

### 1. **Replace the sort display label ternary chain with COLUMN_CONFIG lookup**
- The dropdown already uses `COLUMN_CONFIG[colKey].label` for display names
- The sort display (line 8823-8834) still has a manual ternary chain that must be kept in sync
- Could replace with: `const label = opt.key === 'custom' ? 'Manual Order' : COLUMN_CONFIG[Object.keys(COLUMN_CONFIG).find(k => COLUMN_CONFIG[k].sortKey === s.column)]?.label || s.column`
- Low priority — the manual chain works and is readable

- User had to remind AI to add this step. The release checklist in CLAUDE.md should include "Update TODO.md (remove completed tasks)" — which it already does, but was missed in practice

## Final Thoughts

This was a textbook "UI control over existing infrastructure" release. The sort state, comparison logic, and per-folder persistence all existed — the only missing piece was a way for cover view users to access it. The UX review pass before implementation was the most valuable step: it added the dropdown caret for affordance, confirmed the Custom Order graying behavior, and identified the latent `myRating` label bug. Total effort was minimal because every layer (click-outside, ESC, dropdown styling, sort logic) followed established patterns.

**Key Takeaway**: When adding a UI control over existing infrastructure, spend more time on UX review than on coding — the affordance details (clickability caret, disabled states, discoverability hints) are where the value lives.
