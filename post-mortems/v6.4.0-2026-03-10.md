## 🎯 What Worked Well

### 1. **UX Naming Discussion Before Implementation**
- User and Claude debated Views vs. My Library vs. Quick Access; converged on Views/Folders with specific tooltips
- Discussion also surfaced the concept of `__views__` as a clickable nav destination (right-pane card grid), modeled after `__library__`
- **Lesson**: Spending time on naming and metaphor before coding leads to cleaner, more coherent features. The tooltip copy ("Different ways to see the same books — not separate copies") was the conceptual key that made "Views" feel right.

### 2. **Backup Format Compatibility — Already Done**
- Pinned tag folders were already stored as a separate `organization.pinnedTagFolders` array in backups (distinct from `organization.folders`)
- No migration needed — the split between Views and Folders existed implicitly in the data model
- **Lesson**: Check backup format before designing the split. The data model often already encodes the right structure before the UI does.

### 3. **Parallel Alpha Commits**
- Each discrete UX feature (bold items, chevron, single scroll, simplified headers) shipped as its own alpha commit
- Made it easy to bisect when the JSX parse error appeared in alpha.4
- **Lesson**: One concern per commit during alpha development makes debugging straightforward.

## ❌ Mistakes Made

### 1. **Missing `</div>` for New Scroll Container (alpha.4 → alpha.5)**
- Added a `<div className="flex-1 overflow-y-auto folder-scroll-container">` in Edit 1 of the single-scroll conversion, then removed a `</div>` in Edit 2 (the old sticky close), but never added a closing tag for the new outer scroll div
- Result: JSX parse error "Unexpected token, expected '}'" at the return statement's closing `);` — confusing error for a missing HTML tag
- The error location (end of file) makes it non-obvious that the problem is in the middle of the component
- **Fix**: Added the missing `</div>` in alpha.5. Going forward: when adding a wrapping div in a multi-edit sequence, mentally track "this div needs a close somewhere" and add a TODO comment placeholder if doing it in stages.

### 2. **Div Balance Across Multi-Edit Sequences**
- The single-scroll conversion was planned as 3 edits across 2 sessions (session boundary at edit 1). Edit 2 removed an "orphaned" div close without verifying the new outer wrapper had its own close.
- Both edits were structurally correct in isolation; the bug was in their interaction
- **Fix**: When a feature spans multiple edits/sessions, explicitly track the open/close delta as a number (e.g., "Edit 1: +1 open, +1 close = net 0; new outer div = net -1 close needed"). Don't rely on mental model across session boundaries.

### 3. **`node -e` with Template Literals Containing Backticks**
- Attempted to use `node -e "... \`template\` ..."` in bash, which fails because backticks are interpreted by the shell before node sees them
- **Fix**: Always use `cat > /tmp/script.js << 'SCRIPT' ... SCRIPT && node /tmp/script.js` for node scripts with template literals or complex strings. The single-quoted heredoc delimiter prevents all substitution.

## 📚 Lessons Learned

### 1. **JSX "Expected '}'" at End of File = Unclosed Tag Somewhere in the Middle**
- When Babel's JSX parser reports "Unexpected token, expected '}'" at the `);` closing the return statement, the real problem is an unclosed JSX element — the parser ends up "inside" it and expects `}` to close an expression container rather than `)` to close the return
- **Diagnosis**: Count `<div>` opens vs `</div>` closes in the affected region; look for the edit that added a wrapper without adding a corresponding close
- **Why it matters**: This error will appear again whenever multi-step div restructuring is done. Knowing the diagnosis saves time.

### 2. **Table Column Headers Should Reflect the Data Being Shown**
- The full book column headers (Author, Series, Rating, etc.) were misleading in the Views/Folders right pane — they imply data that doesn't exist for folder/view rows
- Simple fix: `isContainerView` flag selects a minimal thead (Name + Books) for `__library__` and `__views__` contexts
- The same pattern applies anywhere the table renders non-book rows: the header should match the row content
- **Why it matters**: Misleading affordances (sortable columns with no data) erode user trust in the interface.

### 3. **Sticky/Scroll Architecture Refactor Pattern**
- Old pattern: `sticky` div at top → `flex-1 overflow-y-auto` div below (two zones)
- New pattern: single `flex-1 overflow-y-auto` wrapping everything after the sticky; sticky closes earlier
- The "sticky" div now only contains the navigation header (title, back/forward, filter bar) — not the full virtual folder list
- **Why it matters**: The two-zone pattern breaks down when the top zone grows; single-scroll is more resilient.

## Final Thoughts

A clean architectural refactor that had one avoidable bug (missing `</div>` in a multi-edit sequence). The UX naming discussion before coding was the most valuable part of this session — it clarified not just what to call things but what they *mean*, which then drove all the implementation decisions (tooltips, `__views__` as a nav destination, collapse behavior). The single-scroll conversion was straightforward in concept but tricky in execution across a session boundary.

**Key Takeaway**: Track div open/close deltas explicitly when restructuring across multiple edits, especially across session boundaries where mental context is lost.
