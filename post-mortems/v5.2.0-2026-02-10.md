# v5.2.0 Post-Mortem — 2026-02-10

## What was planned
Edit series name and position from the book detail modal.

## What actually happened
The "simple" series edit feature was mostly done by alpha.3. Then **14 more alphas** were spent chasing two systemic bugs that the feature exposed, plus the VS Code extension crashed mid-session forcing a switch to CLI.

## Root causes found

### 1. Global keyboard handler leak (alphas 11-20)
- **Surface bug**: DEL key in modal inputs deleted books from folders
- **Root cause 1**: Per-input `stopPropagation` was missing on multiple inputs
- **Root cause 2**: There are TWO separate `window.addEventListener('keydown', ...)` handlers (`handleKeyDown` and `handleKeyboard`). Fixing one didn't fix the other.
- **Root cause 3**: React synthetic `stopPropagation` doesn't reliably block native `window` listeners. The `isInputFocused` guard also failed because modals can have focus on non-input elements (BODY, spans, table headers).
- **Final fix**: `anyModalOpenRef` checked in BOTH handlers + `isInputFocused` guard + per-input `stopPropagation` (3 layers of defense)
- **Alphas burned debugging**: ~6, mostly because the second listener wasn't discovered until alpha.19

### 2. Backdrop swipe-close (alphas 15-22)
- **Surface bug**: Dragging from inside a modal and releasing on the backdrop closed the dialog
- **Root cause**: All backdrops used plain `onClick` which fires on any click, even when mousedown originated inside the dialog
- **Fix**: `backdropMouseDownRef` pattern requiring both mousedown AND click on the backdrop
- **Scope creep**: Started with 3 dialogs, expanded to all 17

### 3. Tailwind CDN classes not queryable (alpha 17-18)
- Attempted DOM query `document.querySelector('.fixed.inset-0')` to detect modals — returned `null`
- Tailwind CDN doesn't expose utility classes as individual DOM classes
- Wasted an alpha on a dead-end approach before switching to ref-based detection

## What went well
- Diagnostic logging (alpha.19) quickly identified the dual-listener issue
- The `anyModalOpenRef` pattern is clean and future-proof
- All 17 backdrops are now consistently protected
- Memory file updated with key lessons for future sessions

## What could be improved
- **Should have searched for ALL `addEventListener('keydown'` at the start** instead of assuming there was only one handler
- **Should have used refs from the beginning** instead of trying DOM queries (known from prior experience that Tailwind CDN is tricky)
- **Hard-refresh discipline** — at least one false test result came from testing stale code

## Lessons for future work
1. When fixing a global event handler bug, always `grep` for ALL registrations of that event type
2. Don't use DOM queries for Tailwind CDN class detection — use React state/refs
3. Always bump version before testing, and always hard-refresh
4. "Simple" features that touch modal inputs will likely trigger the keyboard leak pattern — check proactively
