# Post-Mortem: 7.6.2 — receipts and honesty

**Date**: 2026-09-02
**Release**: 7.6.2 (app) / 1.7.2 (mobile), prod+dev — the follow-up batch to 7.6.0/7.6.1: toast history, backup receipts, mobile ⊟/⊞ names-only sections, restore echo-push suppression, gen-id suffixes in the freshness display. Plus the same-morning prod graveyard wipe (six dead-channel legacy singles + the `11111111` fixture, ~100 MB).

One-day batch, four alphas, no drama — the interest is in the small lessons.

## ✅ What worked well

1. **The batch theme held.** Five items, one idea — *operations leave receipts, and displays tell the truth* — which made the CHANGELOG write itself and each item reinforce the others (the backup receipt lands in the toast history; the gen suffixes explain the banner the echo-fix quiets).
2. **Ron's first test caught the receipt lying by timing**: the "Backup saved" toast fired *before* Chrome's ask-where picker — a cancel would have made it retroactively false. The fix upgraded the whole flow: `showSaveFilePicker` **first** (real destination, true completion, honest cancel) with the anchor download as fallback. A polish item became a correctness item under one minute of real use — the recurring moral of this whole cycle.
3. **Delete-with-evidence, again**: the prod legacy singles were wiped only after Ron's "are we sure those are mine?" challenge forced the TTL/activity review (five already self-expiring, last writes June–July, zero new-format keys, the fixture referenced nowhere in code) — plus the mirror-not-vault argument as backstop. GoatCounter's "at least one other user" was the right paranoia even though it changed nothing.
4. **The dev-machine blind-spot genre is now named and predictable**: guard always skips, banner never fires, copy-suffix never shows — all one geometry. Ron's screenshot of a missing `(copy …)` suffix was answered in one paragraph instead of an investigation, because the class is documented.

## ❌ What went wrong (small, but recorded)

1. **The toast-before-picker bug shipped to alpha at all** — the author tested with ask-where-to-save off, the user had it on. Browser-setting variance is test-matrix variance.
2. **`showSaveFilePicker` ordering subtlety**: it must be called *before* the seconds of serialization or the click's transient user-activation expires. Got it right first try only because the constraint was known — worth this line so future file-pickers inherit it.
3. **A "make it so" misread** (previous evening): Ron meant "log it," the model built it. Harmless — it became the next morning's pre-done first task — but directive ambiguity at day's end is worth a clarifying question.
4. Behavior change worth watching: users with ask-where-to-save **off** now get a save dialog they didn't have. Defensible for backups (deliberate placement of a safety net); revisit only if it grates.

## Final thought

7.6.0 built the truth-telling; 7.6.2 added the receipts. The pattern across both: every display claim ("saved", "newer", "current") now has a mechanism behind it that can actually know — and the one-minute-of-real-use rule keeps finding the claims that couldn't.
