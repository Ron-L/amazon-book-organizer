## 🎯 What Worked Well

### 1. **Audit-first → design doc → incremental extraction**
- Started with a read-only study that inventoried every mutating op from the undo/redo reducers (the authoritative list), wrote `docs/design/OPERATIONS-REFACTOR.md`, then extracted one operation per commit, browser-tested each.
- **Lesson**: For a cross-cutting refactor, the reducer switch *is* the map. Enumerate from it, spec it, extract incrementally — never big-bang a hot path.

### 2. **Standardized undo/redo feedback at the single dispatcher**
- The scattered per-reducer-case `showToast`s were the drift. Moving them to one place — `recordAction` stamps every action with a `label`; `undo()`/`redo()` always toast it — killed the drift *and* forced coverage (a missing label warns).
- **Lesson**: Cross-cutting feedback belongs at the choke point, driven by data on the object, not sprinkled through the handlers.

### 3. **Evidence-driven course corrections**
- The `moveItems` "dead fallback" discovery (below) and the route-vs-delete decision both came from following evidence over assumption, and both made the result better and smaller.

### 4. **Consolidation paid its own way**
- −387 net lines while *fixing* five latent bugs (homeless books, undo-dup, missing toasts, silent drag undo, terse confirms). One implementation per op is less code, not more.

## ❌ Mistakes Made

### 1. **Built two functions on DEAD code without verifying which handler fires**
- For "book move/copy," I created `moveBooksToFolder`/`copyBooksToFolder` and rewired the drag drop-handlers to them (alphas 2/4/5) — but those `x-readerwrangler` handlers are **dead fallbacks**. The real drag path always sets `x-rw-items`, handled first by `moveItems` (which returns before the fallback). So the "drag consolidation" edited code that never runs.
- **What surfaced it**: the user tested and reported **"no console output"** from my diagnostic logs — the clue that my functions weren't being called at all.
- **What should have happened**: before consolidating "the drag path," confirm *which* handler actually fires (a one-line log, or trace the drag `dataTransfer` formats). I assumed from code structure.
- **Fix**: collapsed everything onto `moveItems` (the path that was already correct) and deleted the redundant functions (alpha.8). Net result is cleaner — but several alphas were spent on the wrong target.

### 2. **The Book List "+" toast took four iterations**
- alpha.10 added a toast (premature, at click) → alpha.11 fixed the undo *label* but not the toast timing → alpha.12 moved the toast to after-naming → alpha.13 added the Escape path. Each was a round-trip.
- **What should have happened**: for a *create-then-inline-name* flow, map all three exits (Enter / blur / Escape) and the record-vs-name timing **up front**, in one pass.

## 📚 Lessons Learned

### 1. **Verify the live code path before refactoring it**
- Code that *looks* like the handler may be a dead fallback. Instrument ("which handler fires? how many times?") or trace the event data format *first*. The dead-fallback session cost the most rework of the whole refactor.

### 2. **React blur-on-unmount timing is unreliable — guard synchronously**
- Escape unmounts the rename input; whether `onBlur` also fires is uncertain, and `undoStackRef`/state lag a tick. A plain `useRef` set synchronously (`blFinalizedRef.current = bl.id`) is the robust once-only guard.

### 3. **`async` a sync function safely by keeping the await conditional**
- `reparentFolder` became `async` for the menu's large-move confirm, but drag callers don't await and pass `confirmLarge` falsy → no `await` → the mutation still runs synchronously. Adding an optional confirm doesn't have to break the fire-and-forget callers.

## 🤖 AI Collaboration Insights

### Practices That Required User Prompting
- The **"no console output"** report is what broke my wrong mental model — a reminder to trust an unexpected test result over the model, immediately, rather than theorizing around it.
- Good scope calls the user made: **route (don't delete)** the dead fallbacks (since not every drag source is 100%-verified to set `x-rw-items`), and **leave `moveItems`** as the atomic drag path rather than forcing it into `reparentFolder`.

### What Ground Rules Helped
- Alpha-commit-before-test kept 15 iterations bisectable.
- "Study first, report before changing" on #4 avoided churning the genuinely-distinct ops (reorder, copy).
- Divergence pre-flight (again) — this time a clean fast-forward, verified not assumed.

## Final Thoughts

The refactor did exactly what it set out to: one implementation per operation, five drift bugs gone, and the codebase ~390 lines lighter. The sharp lesson is the dead-fallback detour — I refactored code that never executed because I read structure instead of confirming behavior, and it took the user's "no console output" to catch it. Cheap to prevent (one log), expensive to discover late.

**Key Takeaway**: Before you refactor "the path," prove which path actually runs — a single log beats a confident mental model.
